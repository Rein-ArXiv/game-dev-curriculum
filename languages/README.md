# 프로그래밍 언어 시리즈 지도

`languages/`는 게임 스크립트, 셰이더 DSL, 퀘스트 조건식, 콘솔 명령, 비주얼 스크립팅을 “문자열 처리”가 아니라 작은 언어 구현 문제로 다루는 공통 CS 축이다.

## 구현 흐름

```text
source
  -> token
  -> CST/AST
  -> symbol table
  -> typed AST / IR
  -> bytecode or machine IR
  -> runtime / VM
  -> engine binding
```

## 읽는 순서

| 문서 | 역할 |
|---|---|
| `part01_frontend_semantics.md` | 소스 코드를 토큰, 구문 트리, symbol, type이 붙은 구조로 바꾼다. |
| `part02_execution_runtime.md` | AST 또는 바이트코드를 실제 상태 변화로 실행하고 호출·클로저·객체를 구현한다. |
| `part03_garbage_collection.md` | 객체 그래프의 도달 가능성, 회수 알고리즘, write barrier, 정지 시간의 비용을 다룬다. |
| `part04_compiler_optimization_abi.md` | 의미를 보존하며 IR을 낮추고 최적화한 뒤 ABI와 기계 경계에 맞춘다. |
| `part05_jit_compilation.md` | 실행 프로파일에 따라 코드를 특수화하고, 가정 실패 시 상태를 복원하는 적응형 런타임을 구현한다. |
| `part06_engine_scripting.md` | VM·컴파일러 산출물을 엔진 객체, 핫 리로드, 샌드박스, 디버깅 경계에 연결한다. |
| `part07_reflection_metadata.md` | 컴파일·실행 시점 메타데이터를 생성하고 에디터·직렬화·바인딩에 연결한다. |

## 공통 핵심으로 보는 이유

게임 개발자는 항상 크고 작은 언어를 만든다. 설정 파일, 데이터 검증 규칙, 셰이더, 스크립트, 노드 그래프, 명령 콘솔은 모두 입력을 해석하고 의미를 고정하며 오류를 보고해야 한다. 이 시리즈의 목적은 범용 컴파일러 전문가가 되는 것이 아니라, 도구와 런타임이 이해할 수 있는 언어를 설계하는 공통 원리를 익히는 것이다.

## 완료 기준

- 구문과 의미를 분리해 설명할 수 있다.
- 이름 해석과 타입 검사가 어떤 산출물을 남기는지 설명할 수 있다.
- 인터프리터, 바이트코드 VM, 컴파일러의 비용과 보장 차이를 비교할 수 있다.
- GC와 호스트 경계가 프레임 예산과 안정성에 미치는 영향을 설명할 수 있다.
- JIT의 특수화, inline cache, 역최적화가 의미 보존과 어떤 계약을 맺는지 설명할 수 있다.
- 엔진 스크립팅에서 바인딩, 핫 리로드, 샌드박스, 디버깅을 하나의 런타임 계약으로 볼 수 있다.
