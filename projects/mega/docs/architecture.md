# Mega Defense 아키텍처

## 단일 코드베이스 원칙

프로젝트는 학습 순서별 소스 스냅샷을 보관하지 않는다. `include/`의 엔진 라이브러리,
`games/defense/`의 제품 코드, `tests/`의 검증 코드가 한 CMake 그래프를 이룬다. 특정 개념을
도입한 순서와 실패 사례는 개발 문서가 소유하고, 컴파일되는 코드는 현재의 완성 상태만 표현한다.

## 시뮬레이션 시간

listen host, 전용 서버, 싱글플레이는 60Hz 고정 스텝으로 `GameWorld::Step`을 호출한다. 렌더 프레임의 실제
경과 시간을 누적하고 `1/60s`마다 시뮬레이션을 전진시킨다. 한 렌더 프레임에서 최대 다섯 틱만
보충해 긴 정지 뒤 spiral of death를 막는다. 렌더 빈도와 시뮬레이션 속도는 분리된다.

게임 스텝은 다음 순서다.

1. 웨이브 스폰
2. 경로를 따른 적 이동
3. 타워 타게팅과 발사
4. 발사체 이동과 피해·보상
5. 사망 객체 정리
6. 승패 판정

렌더러와 네트워크는 이 상태를 읽지만 직접 수정하지 않는다.

## 맵과 배치 불변식

`DefenseMap`은 타일 타입과 순서 있는 경로를 소유한다. 외부 레벨 로더는 다음 조건을 모두
만족해야 맵을 채택한다.

- 모든 행의 폭이 같다.
- `S`와 `C`가 각각 하나다.
- `S`, 모든 `P`, `C`가 상하좌우로 연결된다.
- 방문하지 않은 다음 경로 셀이 매 지점 하나뿐이다.
- `C`에 도달했을 때 모든 경로 셀을 소비했다.

타워 배치는 호스트 `GameWorld`에서 다시 검증한다. 건설 가능 셀인지, 기존 타워와 겹치지
않는지, 타워 상한 16개를 넘지 않는지 확인한 뒤 셀 중앙으로 스냅한다. 클라이언트의 초록색
미리보기는 편의 기능일 뿐 보안 경계가 아니다.

## 권위 네트워크

권위 프로세스만 `GameWorld`를 전진시킨다. 권위 프로세스는 플레이어가 함께 실행하는
listen host일 수도 있고, 렌더와 입력이 없는 `mega_defense_server`일 수도 있다. 클라이언트는
`Place`, `Upgrade`, `Sell`, `Target` 명령만 보낸다. 명령에는 32비트 단조 시퀀스가 있고,
권위 측은 클라이언트별로 정확히 다음 번호만 한 번 처리한다. 클라이언트는 자기 스냅샷의
누적 확인 번호를 받을 때까지 미확인 명령을
100ms마다 재전송한다. 최신성 비교는 두 값의 거리가 시퀀스 공간 절반보다 작다는
네트워크 윈도우 불변식 아래 unsigned 차이를 사용하므로 `UINT32_MAX`에서 0으로 넘어가도
ACK가 과거 명령을 새 명령으로 오인하지 않는다.

권위 프로세스는 60Hz 시뮬레이션 세 틱마다 20Hz 스냅샷을 전송한다. 스냅샷은 다음 상한으로
1200바이트 이하를 유지한다.

- 타워 16개
- 적 64개
- 발사체 20개

위치는 1/8 픽셀, 체력은 1/4 단위의 16비트 정수로 양자화한다. 타워·적·발사체는 안정적인
32비트 ID를 포함한다. 디코더는 magic, 버전, payload 길이, 컬렉션 상한, enum 범위,
체력 범위를 검사하고 남거나 부족한 바이트가 있으면 패킷 전체를 거부한다.

클라이언트는 최근 스냅샷 여덟 개를 보관하고 최신 시점보다 약간 과거를 렌더한다. 동일 ID의
적·발사체 위치와 적 체력, 코어 체력을 두 스냅샷 사이에서 보간한다. 타워 건설처럼 불연속인
상태는 최신 권위 값을 사용한다. 보간 시각은 `double`로 누적해 장시간 세션에서 `float`가
연속 정수 tick을 구분하지 못하는 문제를 피한다. tick이 32비트 경계를 넘으면 wrap 이전
표본을 버리고 새 보간 epoch를 시작한다.

`LoopbackNet`은 손실·재정렬·지연을 결정적으로 주입하는 알고리즘 테스트 백엔드다.
`UdpTransport`는 listen host와 클라이언트가 사용하는 단일 피어 비차단 IPv4 소켓이다.
listen host는 첫 데이터그램 주소를 즉시 고정하지 않고, 상위 프로토콜이 Hello의 magic,
버전, 길이를 검증한 뒤에만 `AcceptLastSender()`를 호출한다.

전용 서버는 송신자 주소를 데이터그램과 함께 반환하는 `UdpServer`를 사용한다. 각 끝점은
독립된 `ClientSession`을 가지며 마지막 명령 번호와 누적 ACK도 독립적이다. 서버는 같은
매치의 플레이어 두 명이 승인된 뒤 60Hz 시뮬레이션을 시작하고, 각 클라이언트에 자기 ACK가
들어간 스냅샷을 보낸다.

전용 서버의 `AdmissionHello`에는 라이브 서비스가 발급한 게임 토큰이 들어간다. 토큰은
`base64url(JSON).base64url(HMAC-SHA256)`이며 서버는 공유 비밀로 서명을 검증한 뒤 다음을
확인한다.

- 토큰 종류가 `game`이다.
- `ServerId`가 현재 프로세스의 ID와 같다.
- 만료 시각이 현재 시각보다 뒤다.
- 한 `TokenId`와 한 플레이어가 서로 다른 UDP 끝점에 중복 결합되지 않는다.
- 한 서버 프로세스에는 같은 `MatchId`의 정원 두 명만 입장한다.

HMAC은 토큰의 위조를 막지만 이후 UDP 명령의 기밀성이나 패킷별 인증을 제공하지 않는다.
현재 세션은 끝점 결합에 의존하므로 NAT rebinding, 재접속, AEAD, rate limiting은 별도 운영
기능이다. 이 제한 때문에 전용 서버 경로도 그대로 인터넷에 노출할 완성형 보안 경계는 아니다.

## 렌더와 에셋

게임은 RGBA8 CPU 프레임버퍼에 타일·스프라이트·HUD를 그린다. 표시 단계만 바꿀 수 있다.

- GDI: CPU 프레임버퍼를 창에 직접 blit
- Vulkan: staging buffer에서 이미지로 복사하고 풀스크린 삼각형으로 swapchain present

PPM 로더는 P3 형식, 최대 256x256, 채널 범위, 정확한 픽셀 수를 검증한다. 순수 마젠타를
투명 키로 바꾼다. 외부 파일이 없거나 잘못됐으면 내장 절차 스프라이트를 사용하므로 리소스
실패가 게임 규칙 실패로 전파되지 않는다.

레벨과 웨이브도 외부 파일에서 읽지만 부분 성공을 허용하지 않는다. 레벨은 경로 불변식을
모두 만족해야 채택하고, 웨이브는 모든 행의 개수·체력·속도·보상·간격·적 종류가 범위
안이어야 한다. 한 항목이라도 잘못되면 해당 파일 전체를 내장 기본값으로 교체한다. 외부
데이터와 내장 데이터가 섞여 난이도나 경로가 우연히 달라지는 상태를 만들지 않는다.

`balance.script`는 시작 골드, 코어 체력, 적 체력·속도·보상 배율을 계산한다. 파일은
64KiB로 제한하고 파싱·실행 성공 뒤에도 각 출력의 유한성과 범위를 검사한다. 하나라도
실패하면 다섯 값을 모두 기본 구성으로 되돌린다.

이 파일은 재배포 없이 교체할 수 있으므로 "끝나지 않는 프로그램"도 입력의 하나다. 그래서
크기·값 검사만으로는 부족하고, 인터프리터 자체가 세 가지 상한을 갖는다: 실행 전체에 걸리는
스텝 예산(`Script::kDefaultStepBudget`, Eval 노드 방문 100만 회), 파서·실행 재귀 깊이
상한(`kMaxNestingDepth` = 64), 그리고 모르는 토큰을 반드시 소비하는 파서 전진 보장이다.
셋 다 While 노드 하나가 아니라 `Run()` 한 번 전체에 걸린다 — 노드마다 초기화되는 지역
카운터는 중첩되면 상한이 곱해져 상한 구실을 못 하기 때문이다. 상한을 넘긴 실행은 조용히
멈추지 않고 `<파일 경로>:<줄>: …` 형식의 진단을 남기며, 로더는 그 문자열을 표준 오류로
찍고 기본 구성으로 진행한다. "전체 폴백"은 파싱·범위뿐 아니라 실행 시간에도 적용된다.

스크립트는 호스트와 싱글플레이 초기화
때만 실행되고 매 틱 실행되지 않는다. 협동 클라이언트는 권위 스냅샷을 표시하므로 로컬
스크립트 값으로 월드 상태를 만들지 않는다.

물리 키는 `InputMap`에서 액션으로 바뀐다. 프레임 시작마다 눌림·놓임 edge를 비우고 현재
키 상태를 동기화해, 키를 누르고 있는 동안 강화나 판매 명령이 매 프레임 반복되지 않게
한다. 발사체는 목표의 안정 ID를 보존하고 살아 있는 목표 위치를 추적한다. 명중과 광역
피해 후보는 물리 모듈의 원-원 판정을 사용한다. 충돌 뒤 생성되는 파티클은 렌더 전용
상태이며 `GameWorld`와 네트워크 스냅샷에 포함되지 않는다.

싱글플레이의 `P`는 시뮬레이션 누적 시간을 버리고 고정 스텝 전진만 멈춘다. 입력과 렌더는
계속 처리하므로 정지 중 건설·강화가 가능하다. 협동에서는 호스트 시간과 클라이언트 화면의
일시정지 정책을 프로토콜로 정의하지 않았으므로 이 기능을 제공하지 않는다.

## 영속과 지표

매치 종료 정산은 프로필 갱신과 매치 기록을 한 WAL 트랜잭션에 넣고 마지막 COMMIT 마커 뒤
`fsync`/`_commit`한다. 복구는 커밋된 완전한 접두사만 재생하므로 잘린 마지막 트랜잭션은
부분 적용되지 않는다.

운영 레지스트리는 프레임 시간 히스토그램, 원격 명령 카운터, 전송 스냅샷 카운터·크기
히스토그램, 스냅샷 잘림 카운터를 집계한다. 집계한 값은 전부 종료 시 로컬 콘솔 한 줄에
출력한다(`frame_p95`, `snapshot_bytes_p95`, `snapshot_bytes_max`, `snapshots_truncated`) —
수집만 하고 출력하지 않는 지표를 두지 않는다는 것이 이 레지스트리의 불변식이다. 외부 수집
시스템 전송은 구현 범위가 아니다. 이 레지스트리는 `mega_defense`의 것이고, 전용 서버는
자기 루프 통계를 직접 출력한다.

## 라이브러리 소유권

최종 게임이 직접 사용하는 모듈과 독립적으로 검증하는 모듈을 구분한다. 이 구분은 손으로 유지하는
목록이 아니라 컴파일러의 의존성 출력에서 계산한다 — 제품 진입점을 컴파일할 때 실제로 열린
파일만 제품 경로다.

| 구분 | 모듈 | 이유 |
|---|---|---|
| 제품 경로 | `game`, `net`, `render`, `db`, `io`, `platform` 창·오디오·경로·VFS·표시·신호, `math` vec·scalar·aabb, `physics` shape·rigid_body·narrow phase, `engine` 입력·파티클, `tools` 스크립트, `serialize`, `live` 입장 토큰·지표 | 실제 한 판과 협동 세션에 필요 |
| OS 경계 | `platform/window`, `platform/audio_device`, `platform/vk_present`, `platform/paths`, `platform/process`, `io/file`, `net/udp_*` | 입력·출력·전송·표시·종료 신호의 유일한 입구 |
| 참조 구현 | `memory`, `containers`, `ecs`, `jobs`, `sync`, `profiler`, 범용 `ai`, `mp` lockstep·rollback, `physics` 솔버·적분, `math` 회전·공간 분할·노이즈, `engine` 애니메이션·IK·오디오 믹서·리소스, `live` 경제·플래그·패치, `tools` 파이프라인·에디터·절차 생성 | 이 게임의 규모와 규칙이 요구하지 않음. 근거는 축 소유권 문서에 등재하고 독립 테스트로 검증 |

축 단위의 판정과 근거는 [`AXIS_OWNERSHIP.md`](AXIS_OWNERSHIP.md), 헤더 단위의 사실은 빌드가
생성하는 `PRODUCT_LAYERS.md`가 소유한다. 도달 불가인데 `LAB_ONLY.md`에 등재도 되지 않은
제3의 상태는 빌드 실패다.

타게팅 모드와 경로 추종은 게임 규칙 안의 도메인 AI다. 범용 A*·Flow Field·Behavior
Tree를 이름만 사용하려고 같은 계산을 반복하지 않는다. 최대 16개 타워와 64개 적에서는
작업 스케줄러의 동기화 비용이 직렬 계산보다 클 수 있으므로 프로파일 근거 없이 병렬화하지
않는다. 불필요한 모듈 호출로 통합 수를 늘리는 대신 실제 수명·권위·비용 경계가 생기는
곳에서만 공용 모듈을 호출한다.

## 계층 규칙

`games/`는 OS API를 직접 부를 수 없다. 소켓·창·파일·오디오·GPU·신호·환경 변수 헤더의
인클루드가 금지되고, 전이 인클루드로 손에 닿는 OS 타입 이름과 함수 호출도 금지된다.
게임 진입점은 150줄을 넘을 수 없고 `games/` 아래에는 헤더를 둘 수 없다.

`scripts/check_layers.py`가 구성 시, 매 빌드, 그리고 `layer_rules` 테스트에서 이 규칙을
검사한다. 감사가 찾은 최악의 결함 — 제품이 `main.cpp` 익명 네임스페이스에서 복제 버퍼를
재구현하고 `include/net/`은 테스트만 링크한 상태 — 은 진입점이 `<winsock2.h>`를 들이마실 수
있었기 때문에 가능했다. 원재료가 손에 닿으면 누구든 그 자리에서 다시 만든다. 인클루드를
막으면 그 물리적 경로가 사라진다.

## 검증 경계

- 게임 규칙: 승리·패배·경제·웨이브·맵·배치
- 프로토콜: 명령·스냅샷 왕복, 손상·절단 거부, MTU 상한
- 실제 네트워크: 로컬 UDP 왕복과 명령→권위 검증→확인 스냅샷
- 프로세스 경계: listen host·클라이언트 왕복, 전용 서버와 두 UDP 끝점의 토큰 입장·공유 상태
- 보안 계약: HMAC 알려진 벡터, 서버 audience·만료·변조 거부
- 장애 모델: 결정적 손실·지연·재정렬 아래 세 ordered 명령의 누적 ACK 수렴
- 장기 시뮬레이션: 반복 매치의 유한 상태, ID 유일성, 엔티티·wire 상한
- 외부 콘텐츠: 정상 웨이브 로드와 손상 파일의 원자적 전체 폴백
- 스크립트 콘텐츠: 정상 밸런스 계산과 구문·실행·범위 실패의 전체 폴백
- 엔진 경계: 입력 눌림 edge와 파티클 수명·제거
- 물리 적용: 이동 표적 추적과 원 충돌 기반 명중·광역 피해
- 영속: 프로세스 재오픈 뒤 프로필·최고 기록 복구
- 렌더: 래스터 픽셀, 스프라이트 투명도·클리핑·파일 검증
- GPU: 실제 Vulkan 장치·스왑체인 5프레임 present(`mega_defense_gpu_selftest`). 장치·창·SDK가
  없는 환경에서는 실패가 아니라 Skipped로 보고한다 — 검증됐다는 뜻이 아니라 이 머신에서는
  물을 수 없다는 뜻이다
- 계층 규칙: `games/`의 OS API 직접 호출과 진입점 줄 수 상한(`layer_rules`)
