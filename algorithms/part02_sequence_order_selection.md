## 들어가며

정렬과 이진 탐색은 짧은 코드 때문에 쉬워 보이지만, 실제 계약은 순서 관계와 경계 구간에 숨어 있다. 비교자가 추이성을 잃으면 정렬 결과뿐 아니라 알고리즘의 종료 전제까지 깨진다. 중복 키가 있는 배열에서 이진 탐색이 임의의 일치 원소를 반환하면 삽입 위치, 범위 질의, 결정적 재생이 서로 다른 의미를 갖게 된다.

게임 런타임은 모든 원소를 완전히 정렬할 필요가 없는 경우가 많다. 가까운 광원 몇 개, 가장 위험한 적 하나, 화면에 보이는 상위 점수처럼 선택과 부분 정렬이 실제 요구다. 입력 크기만 보고 알고리즘을 고르면 비교 횟수는 줄어도 이동 바이트와 캐시 미스가 늘 수 있다.

이 글은 순서 관계를 명세하고, 이진 탐색·정렬·선택의 정확성을 불변식으로 증명한다. 비교 모델의 하한과 정수 키 정렬의 예외, 안정성·메모리·지연 분포를 함께 분석해 실제 워크로드에 맞는 선택 기준을 만든다.

## 1. 순서 문제의 계약

정렬 문제는 입력 수열 $A=(a_0,\dots,a_{n-1})$을 같은 원소의 순열 $A'$로 바꾸되, 모든 인접 원소가 지정된 순서를 만족하게 하는 문제다. 출력에는 두 조건이 동시에 필요하다.

$$
\forall i\in[0,n-2],\quad \neg less(A'_{i+1},A'_i)
$$

```text
출력의 순서가 올바르다.
출력의 multiset이 입력의 multiset과 같다.
```

첫 조건만 검사하면 원소를 잃거나 복제한 잘못된 구현도 통과할 수 있다. 정렬은 순서 변경일 뿐 원소 집합을 바꾸는 연산이 아니다.

### 엄격 약순서

일반 정렬이 요구하는 비교자 `less(a, b)`는 엄격 약순서(strict weak ordering)를 이뤄야 한다.

- 비반사성: `less(a, a)`는 거짓이다.
- 비대칭성: `less(a, b)`가 참이면 `less(b, a)`는 거짓이다.
- 추이성: `a < b`이고 `b < c`이면 `a < c`다.
- 비교 불가능성의 추이성: `a`와 `b`, `b`와 `c`가 각각 동치라면 `a`와 `c`도 동치다.

여기서 동치는 값의 완전한 동일성이 아니라 `!less(a,b) && !less(b,a)`로 정의되는 순서 동치다. 점수가 같은 두 플레이어는 ID가 달라도 점수 비교에서는 같은 동치류에 속할 수 있다.

```cpp
auto byScoreThenId = [](const Player& a, const Player& b) {
    if (a.score != b.score) return a.score > b.score;
    return a.id < b.id;
};
```

동률 규칙을 ID까지 확장하면 완전한 결정적 순서를 얻는다. 반대로 `<=`를 사용하면 `less(a,a)`가 참이 되어 계약을 위반한다.

### 순서와 키 변환

비교가 비싸면 원소에서 키를 한 번 추출하는 decorate-sort-undecorate 패턴을 사용할 수 있다.

```text
원소 x
  -> (key(x), original_index, x)
  -> key와 index로 정렬
  -> x만 회수
```

키 캐시는 비교마다 문자열 정규화나 거리 계산을 반복하지 않게 한다. 그러나 키 저장 메모리와 원소 이동량이 늘어난다. 키가 원소 변경 뒤 오래 남으면 stale key가 되므로 계산과 정렬의 수명 경계를 함께 고정해야 한다.

## 2. 이진 탐색과 경계 불변식

이진 탐색은 정렬된 범위에서 한 번의 비교로 후보 구간을 절반가량 줄인다. 핵심은 중간 인덱스 계산이 아니라 **답이 들어 있는 구간의 의미를 반복 내내 보존하는 것**이다.

### `lower_bound`의 명세

`lower_bound(A, x)`는 `A[i] < x`가 거짓인 최초 인덱스, 즉 `A[i] >= x`인 첫 위치를 반환한다. 모든 원소가 `x`보다 작으면 `n`을 반환한다.

반열린 구간 `[lo, hi)`를 사용하면 다음 불변식이 자연스럽다.

```text
[0, lo)의 모든 원소는 x보다 작다.
[hi, n)의 모든 원소는 x보다 작지 않다.
답은 항상 [lo, hi]에 있다.
```

```cpp
template<class T, class Less = std::less<>>
std::size_t LowerBound(std::span<const T> a, const T& x, Less less = {}) {
    std::size_t lo = 0;
    std::size_t hi = a.size();

    while (lo < hi) {
        const std::size_t mid = lo + (hi - lo) / 2;
        if (less(a[mid], x)) lo = mid + 1;
        else                 hi = mid;
    }
    return lo;
}
```

`a[mid] < x`이면 `mid`까지는 답이 될 수 없으므로 `lo=mid+1`이다. 그렇지 않으면 `mid`가 최초 위치일 가능성이 남으므로 `hi=mid`다. 두 경우 모두 구간 길이 `hi-lo`가 줄고 음이 아닌 정수이므로 반복은 종료한다. 종료 시 `lo==hi`이며 불변식에 의해 그 위치가 답이다.

### 중복과 범위 질의

`upper_bound(A,x)`는 `x < A[i]`인 최초 위치다. 두 경계를 조합하면 같은 키의 반열린 범위를 얻는다.

$$
[lower\_bound(x), upper\_bound(x))
$$

이 명세는 임의의 일치 위치를 반환하는 탐색보다 조합성이 좋다. 존재 검사는 `i<n && A[i]==x`, 삽입은 `i`, 중복 개수는 `upper-lower`로 표현된다.

### 연속값에서의 이진 탐색

정수 인덱스가 아니라 단조 predicate `P(t)`가 거짓에서 참으로 한 번 바뀌는 경계를 찾을 수도 있다. 충돌까지의 시간, 허용 오차를 만족하는 LOD 거리, 일정 품질을 달성하는 예산이 예다.

부동소수점 구간에서는 `lo==hi`를 종료 조건으로 쓸 수 없다. 반복 횟수나 오차 폭을 계약해야 한다.

```cpp
for (int iter = 0; iter < 48; ++iter) {
    const double mid = std::midpoint(lo, hi);
    if (predicate(mid)) hi = mid;
    else                lo = mid;
}
```

단조성이 깨지면 이진 탐색은 의미가 없다. 노이즈가 섞인 측정값을 predicate로 사용하면 한 번의 표본 때문에 경계 방향이 뒤집힐 수 있다.

## 3. 비교 정렬의 하한

비교 정렬은 두 키의 상대 순서를 묻는 비교 결과만으로 입력 순열을 구별한다. 서로 다른 키 $n$개의 가능한 순열은 $n!$개다. 이진 비교 결정 트리가 모든 순열을 구별하려면 잎이 최소 $n!$개 필요하다.

높이가 $h$인 이진 트리의 잎은 최대 $2^h$개이므로

$$
2^h\ge n!,\qquad h\ge \lceil\log_2(n!)\rceil
$$

이다. Stirling 근사를 적용하면

$$
\log_2(n!)
=n\log_2 n-(\log_2 e)n+\frac12\log_2 n+O(1)
=\Theta(n\log n)
$$

을 얻는다. 따라서 일반 비교 정렬은 최악에 $\Omega(n\log n)$번 비교해야 한다.

### 하한의 전제

이 하한은 문제 이름이 아니라 연산 모델에 붙는다. 정수 키의 비트나 범위를 직접 사용하면 비교 결정 트리 밖으로 나간다.

- Counting sort: 키 범위가 $[0,k)$일 때 $O(n+k)$
- Radix sort: $d$개 digit을 안정적으로 처리할 때 $O(d(n+k))$
- Bucket sort: 입력 분포 가정 아래 기대 선형 시간 가능

키 범위가 넓거나 sparse하면 `k` 크기의 배열 초기화가 입력 처리보다 비싸질 수 있다. Radix sort도 패스마다 전체 데이터를 읽고 쓰므로 메모리 대역폭과 임시 버퍼가 비용을 결정한다.

### 하한과 실제 시간

비교 횟수의 최적성과 실행 시간의 최적성은 동일하지 않다. 실행 시간은 대략 다음 비용의 합이다.

$$
T \approx C_{cmp}N_{cmp}+C_{move}B_{move}+C_{miss}N_{miss}+C_{alloc}N_{alloc}
$$

큰 객체를 직접 정렬하면 비교는 적어도 이동 바이트가 크다. 인덱스나 포인터를 정렬하면 이동은 줄지만 후속 순회가 간접 참조로 바뀐다. 어느 쪽이 빠른지는 객체 크기와 후속 접근 패턴에 달려 있다.

## 4. Divide-and-Conquer 설계

Divide-and-conquer는 입력을 작은 부분 문제로 나누고(divide), 각각 해결한 뒤(conquer), 결과를 결합한다(combine). 재귀를 사용한다는 사실만으로 divide-and-conquer가 되는 것은 아니다. 부분 문제 크기가 실제로 줄고, 결합 결과가 원문제의 모든 조건을 보존해야 한다.

### 설계 절차

```text
분할: 어떤 축으로 나누면 부분 문제가 같은 형태가 되는가?
정복: base case와 재귀 호출은 무엇인가?
결합: 부분 답에서 전체 답을 복원하려면 어떤 정보가 필요한가?
비용: 부분 크기와 결합 비용이 어떤 점화식을 만드는가?
```

균형 이진 분할이고 결합이 선형이면

$$
T(n)=2T(n/2)+\Theta(n)=\Theta(n\log n)
$$

이다. 그러나 분할이 계속 `1`과 `n-1`이면

$$
T(n)=T(n-1)+\Theta(n)=\Theta(n^2)
$$

가 된다. 재귀 깊이와 결합 작업을 실제 분할 크기로 분석해야 한다.

### 역전 수 세기

수열에서 $i<j$인데 $A[i]>A[j]$인 쌍을 inversion이라 한다. 모든 쌍을 검사하면 $O(n^2)$이다. 배열을 절반으로 나누면 inversion은 세 종류다.

```text
왼쪽 절반 내부
오른쪽 절반 내부
왼쪽 원소와 오른쪽 원소 사이
```

앞의 두 종류는 재귀적으로 센다. 두 절반이 정렬돼 있으면 병합 중 오른쪽 원소가 먼저 선택될 때, 아직 남은 왼쪽 원소가 모두 그 오른쪽 원소와 inversion을 이룬다.

```cpp
if (left[i] <= right[j]) {
    output.push_back(left[i++]);
} else {
    output.push_back(right[j++]);
    inversions += left.size() - i;
}
```

결합 단계가 각 원소를 한 번 처리하므로 전체 $O(n\log n)$이다. 핵심은 정렬이라는 부분 답이 cross inversion을 한꺼번에 세는 데 충분한 정보라는 점이다.

### 결합 정보가 부족한 경우

부분 문제의 최적값만 저장해 전체 최적값을 결합할 수 없는 문제도 있다. 왼쪽·오른쪽 구간의 최대 연속합을 결합하려면 각 구간의 전체 합, 최대 prefix, 최대 suffix, 내부 최대값이 필요하다. 결합에 필요한 요약을 찾는 것이 분할 자체보다 중요하다.

### 중복 부분 문제와의 구분

서로 겹치지 않는 부분을 독립적으로 푸는 divide-and-conquer는 결과 cache가 필요하지 않다. 같은 상태가 여러 재귀 경로에서 반복되면 memoization을 검토해야 한다. 문제 분류는 코드 모양이 아니라 부분 문제 사이 관계로 결정한다.

### 병렬성과 cutoff

독립 부분 문제는 병렬 실행하기 쉽지만 task 생성과 동기화 비용이 생긴다. 입력이 작아지면 순차 알고리즘으로 전환하는 cutoff가 필요하다. Cutoff는 점근 복잡도가 아니라 실제 task overhead, cache, 원소 크기로 측정한다.

## 5. 정렬 알고리즘의 설계 공간

정렬 알고리즘은 하나의 순위표가 아니라 입력 특성에 대한 선택 집합이다.

| 알고리즘 | 시간 | 추가 공간 | 안정 | 강점 |
|---|---|---:|---|---|
| Insertion sort | 최악 $O(n^2)$ | $O(1)$ | 가능 | 작고 거의 정렬된 구간 |
| Merge sort | $\Theta(n\log n)$ | 보통 $O(n)$ | 가능 | 순차 접근, 안정 정렬 |
| Heap sort | $O(n\log n)$ | $O(1)$ | 아님 | 최악 상한과 작은 보조 공간 |
| Quick sort | 평균 $O(n\log n)$ | 평균 $O(\log n)$ stack | 아님 | 연속 배열의 지역성 |
| Introsort | 최악 $O(n\log n)$ | $O(\log n)$ stack | 아님 | 범용 비교 정렬 |
| Counting/Radix | 조건부 선형 | $O(n+k)$ | 구현에 따라 | 제한된 정수 키 |

### Insertion sort

앞의 정렬된 prefix에 다음 원소를 삽입한다. 반복 시작 시 `[0,i)`가 정렬돼 있다는 루프 불변식을 사용한다. 역전(inversion) 수가 $I$라면 이동 비용은 $O(n+I)$이므로 거의 정렬된 작은 배열에서 강하다.

### Merge sort

두 정렬 구간을 선형 시간에 병합한다. 병합 중 양쪽 선두 중 작은 원소를 고르면, 출력 prefix가 아직 남은 모든 원소보다 크지 않다는 불변식이 유지된다.

배열 구현은 보조 버퍼가 필요하지만 접근이 순차적이다. 연결 구조나 외부 파일에서는 병합이 원소 전체를 임의 접근하지 않아 특히 유리하다.

### Quick sort와 Introsort

Quick sort는 pivot을 기준으로 작은 구간과 큰 구간을 만든다. 분할 뒤 다음 조건을 보장해야 한다.

```text
왼쪽 원소는 pivot보다 작거나 같다.
오른쪽 원소는 pivot보다 크거나 같다.
모든 입력 원소가 정확히 한쪽 또는 pivot 위치에 남는다.
```

항상 최솟값을 pivot으로 고르는 입력에서는 깊이가 $n$이 되어 $O(n^2)$이다. 무작위 pivot과 median-of-three는 나쁜 입력의 확률을 줄이지만 최악 상한을 제거하지 않는다. Introsort는 재귀 깊이가 한계를 넘으면 heap sort로 전환해 최악 $O(n\log n)$을 회복하고, 작은 구간은 insertion sort로 마무리한다.

### 안정 정렬

안정 정렬은 순서 동치인 원소의 입력 상대 순서를 보존한다. 여러 키를 역순으로 차례로 안정 정렬하거나, 이미 결정된 제출 순서를 동률에서 유지할 때 필요하다.

안정성이 필요하지 않은데 무조건 안정 정렬을 선택하면 보조 메모리와 이동 비용을 지불할 수 있다. 반대로 동률 규칙이 제품 의미인데 불안정 정렬을 쓰면 플랫폼이나 실행마다 결과가 달라질 수 있다.

## 6. 분할과 선택

선택(selection)은 정렬된 전체 순서가 아니라 $k$번째 원소나 상위 $k$개만 구한다. 전체 정렬의 $O(n\log n)$ 비용이 불필요할 수 있다.

### Quickselect

Quickselect는 Quick sort의 분할 뒤 $k$가 들어 있는 한쪽만 반복한다. 균형 분할의 기대 비용은 다음처럼 선형이다.

$$
T(n)=T(n/2)+\Theta(n)=\Theta(n)
$$

그러나 계속 한쪽에 $n-1$개가 남으면 $O(n^2)$이다. 무작위 pivot은 고정된 적대 입력에 대한 기대 선형 시간을 제공한다.

### 최악 선형 선택

Median-of-medians는 원소를 작은 그룹으로 나누어 각 그룹 중앙값의 중앙값을 pivot으로 사용한다. 일정 비율 이상의 원소가 pivot 양쪽에서 제거되므로

$$
T(n)\le T(\lceil n/5\rceil)+T(7n/10+O(1))+O(n)=O(n)
$$

이다. 최악 상한은 좋지만 상수 비용 때문에 범용 라이브러리에서는 무작위·휴리스틱 분할이 흔하다.

### Top-k의 선택

| 요구 | 적합한 방법 | 비용 |
|---|---|---|
| 한 번 $k$번째 값 | Quickselect | 기대 $O(n)$ |
| 상위 $k$를 정렬해 사용 | partial sort | $O(n\log k)$ |
| 스트림에서 상위 $k$ 유지 | 크기 $k$ min-heap | 원소당 $O(\log k)$ |
| 여러 순위 질의 | 전체 정렬 고려 | $O(n\log n)$ 후 질의 $O(1)$ |

거리상 가까운 광원 8개만 필요하면 모든 광원을 정렬할 이유가 없다. 다만 매 프레임 heap을 새로 할당하면 알고리즘 이득이 할당 비용에 묻힐 수 있으므로 저장소를 재사용해야 한다.

## 7. 안정성·결정성·부동소수점

### 결정적 tie-break

동률에서 순서가 지정되지 않으면 올바른 정렬 결과가 여러 개다. 단일 플레이 런타임에서는 문제가 아닐 수 있지만 replay, lockstep, 네트워크 상태 hash에서는 서로 다른 정답이 desync를 만든다.

```cpp
auto deterministic = [](const Command& a, const Command& b) {
    if (a.tick != b.tick) return a.tick < b.tick;
    if (a.priority != b.priority) return a.priority > b.priority;
    return a.sequence < b.sequence;
};
```

`sequence`는 동일 tick·priority에서도 전체 순서를 고정한다. 주소는 프로세스마다 달라질 수 있으므로 tie-break 키로 사용하지 않는다.

### NaN과 순서

IEEE 754 NaN이 피연산자에 포함되면 일반 비교에서 `a<b`, `a>b`, `a==b`는 모두 거짓이다. NaN이 섞인 키를 그대로 비교하면 엄격 약순서의 동치 관계가 의도와 달라진다.

정책은 둘 중 하나여야 한다.

1. 정렬 전에 NaN을 거부하거나 대체한다.
2. NaN을 항상 앞이나 뒤에 두는 명시적 total-order 비교자를 사용한다.

근사 동등성 `abs(a-b)<epsilon`을 비교자에 넣는 것도 위험하다. 근사 동등성은 일반적으로 추이적이지 않아 정렬 계약을 만족하지 않는다. 정렬 키를 정수 구간으로 양자화한 뒤 ID로 tie-break하는 편이 명확하다.

## 8. 외부 정렬과 병렬 정렬

### 외부 정렬

데이터가 메모리보다 크면 임의 접근 비교 정렬보다 I/O 패턴이 중요하다. 외부 merge sort는 메모리에 들어오는 run을 각각 정렬한 뒤 순차 병합한다.

```mermaid
flowchart LR
    A[입력 스트림] --> B[메모리 크기 run 생성]
    B --> C[각 run 내부 정렬]
    C --> D[k-way 순차 병합]
    D --> E[정렬된 출력]
```

병합 fan-in이 크면 pass 수는 줄지만 동시에 유지할 입력 버퍼와 heap이 커진다. 디스크·네트워크 분석 로그에서는 비교 횟수보다 읽기·쓰기 바이트와 순차성이 지배적이다.

### 병렬 정렬

배열을 여러 구간으로 나눠 독립 정렬한 뒤 병합할 수 있다. 이상적인 계산량만 보면 병렬성이 크지만 다음 비용이 생긴다.

- task 생성과 동기화
- 병합 버퍼와 메모리 대역폭 경쟁
- 작은 구간의 부하 불균형
- NUMA 노드 사이 데이터 이동

원소 수가 작거나 비교가 매우 싸면 단일 스레드가 빠르다. 병렬 cutoff는 상수가 아니라 하드웨어와 원소 크기별 측정값이어야 한다.

## 9. 게임 워크로드의 선택 기준

### 렌더 제출

불투명 draw는 pipeline/material 키로 묶어 상태 변경을 줄이고, 투명 draw는 보통 깊이 순서를 요구한다. 하나의 비교자에 모든 목표를 섞으면 품질과 batching 의미가 충돌한다. pass별로 필요한 순서 계약을 분리해야 한다.

키를 64비트 정수로 pack하면 비교 비용을 줄일 수 있지만 bit 폭과 overflow 정책이 공개 계약이 된다. 깊이 양자화가 같은 두 draw에는 안정성이나 명시적 sequence가 필요하다.

### 이벤트와 작업

시간순 이벤트는 매번 전체 정렬하기보다 min-heap이 적합하다. 한 프레임에 모인 명령을 결정적으로 실행하려면 `(tick, priority, sequence)`로 batch 정렬할 수 있다. 요구가 online인지 batch인지가 자료구조를 결정한다.

### 리더보드와 근접 질의

전체 순위가 필요하면 정렬 구조가 맞지만 화면에 상위 100명만 필요하면 top-k 유지가 더 싸다. 가장 가까운 적 하나를 드물게 찾는다면 선형 선택이 공간 색인 구축보다 단순할 수 있다. 호출 빈도와 데이터 갱신 비용까지 포함해야 한다.

### 선택 표

| 워크로드 특성 | 우선 검토할 방법 |
|---|---|
| 작고 거의 정렬됨 | insertion sort 또는 adaptive sort |
| 일반 배열, 안정성 불필요 | introsort 계열 |
| 안정성과 순차 접근 중요 | merge sort 계열 |
| 제한된 정수 키와 대량 데이터 | radix/counting 계열 |
| $k$번째 또는 상위 소수만 필요 | selection 또는 heap |
| 데이터가 메모리보다 큼 | external merge sort |
| 결정적 재생 필요 | 완전한 tie-break와 고정 키 표현 |

## 10. 검증과 측정

### 정확성 속성

정렬은 다음 속성을 함께 검사한다.

```text
인접 역전이 없다.
출력 multiset은 입력과 같다.
안정 정렬이면 동치 키의 원래 순서가 유지된다.
결정적 모드에서는 같은 입력 바이트가 같은 출력 바이트를 만든다.
```

이진 탐색은 빈 배열, 원소 하나, 모든 값 동일, 목표가 범위 밖, 중복 구간 시작·끝을 생성한다. 결과 인덱스 `i`에 대해 `[0,i)`는 모두 목표보다 작고 `[i,n)`은 모두 작지 않은지 직접 검사한다.

선택은 작은 입력을 완전히 정렬한 기준 결과와 비교한다. 분할 구현에는 다음 속성이 필요하다.

```text
분할 전후 multiset이 같다.
pivot 왼쪽과 오른쪽이 분할 predicate를 만족한다.
요청한 k가 유효하면 결과가 정렬 기준의 k번째와 같다.
```

### 적대 입력

- 이미 정렬된 배열과 역순 배열
- 모든 키가 같은 배열
- 두 값만 번갈아 나오는 배열
- pivot 선택을 계속 불균형하게 만드는 배열
- 비교 비용이 긴 공통 접두 문자열
- NaN, 양·음의 0, 무한대가 섞인 실수 키
- 이동 비용이 큰 객체

### 성능 측정

평균 시간 하나만 기록하지 않는다.

```text
원소 수와 키 분포
비교 횟수와 이동 바이트
임시 메모리 peak
P50/P95/P99 실행 시간
branch miss와 cache miss
입력의 기존 정렬 정도
```

정렬 결과를 사용하지 않으면 컴파일러가 작업을 제거할 수 있다. 결과 checksum을 소비하고, 데이터 생성과 정렬 시간을 분리하며, 동일 입력 복사본으로 알고리즘을 비교해야 한다.

---

## 결론

순서 알고리즘의 정확성은 비교자와 경계 구간의 계약에서 시작한다. `lower_bound`는 답을 포함하는 반열린 구간을 보존하고, 정렬은 순서와 multiset 보존을 동시에 만족해야 한다. 비교 정렬의 $\Omega(n\log n)$ 하한은 비교 모델에만 적용되며 정수 키의 구조를 사용하면 다른 비용 교환이 가능하다.

완전 정렬, 선택, top-k, online 우선순위 유지는 서로 다른 문제다. 실제 게임에서는 비교 횟수뿐 아니라 이동 바이트, 캐시, 안정성, 결정적 tie-break, 최악 지연을 함께 측정해야 한다. 가장 빠른 알고리즘은 이름으로 정해지지 않고 입력 분포와 출력 계약으로 정해진다.
