## 들어가며

알고리즘을 선택한다는 것은 코드 모양을 선택하는 일이 아니라, 입력 크기와 분포가 변할 때 비용이 어떻게 증가하고 어떤 조건에서 결과가 옳은지를 계약하는 일이다. `O(n log n)`이라는 표기만으로는 캐시 미스, 할당, 최악 지연, 입력 분포를 설명할 수 없고, 벤치마크 숫자만으로는 아직 보지 못한 입력에서의 동작을 설명할 수 없다.

이론 분석과 실제 측정은 경쟁 관계가 아니다. 복잡도와 정확성 증명은 측정하지 않은 영역을 설명하고, 프로파일과 벤치마크는 비용 모델이 현실을 얼마나 잘 반영하는지 확인한다. 게임 개발에서는 평균 처리량뿐 아니라 프레임 마감, 메모리 상한, 결정성, 실패 시 품질 저하까지 함께 고려해야 한다.

이 글은 점근 표기, 최악·평균·상각 분석, 루프 불변식과 귀납 증명, 무작위 알고리즘, 하드웨어 비용 모델, 재현 가능한 측정을 하나의 분석 절차로 연결한다. 또한 다항시간 환원과 NP-완전성이 “정확한 해법을 더 최적화할 것인가, 문제 계약을 완화할 것인가”를 어떻게 가르는지, 결정 불가능성이 자동 분석의 근본 한계를 어디에 긋는지도 다룬다.

## 1. 문제와 비용 모델

알고리즘 분석 전에 입력, 출력, 허용 오차, 비용 단위를 정의해야 한다.

```text
입력:
  n개의 엔티티 위치와 질의 원

출력:
  원 안에 있는 모든 엔티티 ID

정확성:
  누락과 오탐 없음

비용:
  질의 시간, 갱신 시간, 추가 메모리
```

같은 문제도 계약이 달라지면 알고리즘이 달라진다.

- 가장 가까운 엔티티 하나만 필요하다.
- 반경 안 후보를 대략 찾고 정확 판정은 나중에 한다.
- 결과가 한 프레임 늦어도 된다.
- 월드는 정적이거나 매 프레임 크게 변한다.

기본 RAM 모델은 산술, 비교, 메모리 접근이 일정 비용이라고 가정한다. 이 모델은 큰 구조를 비교하는 데 유용하지만 현대 하드웨어의 데이터 이동 비용을 숨긴다. 따라서 분석은 보통 두 단계로 한다.

1. 연산 수와 메모리 사용량의 증가율을 분석한다.
2. 캐시, 분기, 할당, SIMD, 병렬화, I/O를 포함한 실제 비용을 측정한다.

## 2. 점근 표기

점근 표기는 입력 크기 `n`이 충분히 클 때 증가율을 비교한다.

### Big-O

`f(n) = O(g(n))`은 충분히 큰 `n`에서 `f(n)`이 상수배 `g(n)`을 넘지 않는다는 상한이다.

$$
\exists c>0,\exists n_0,\forall n\ge n_0:\quad 0\le f(n)\le c g(n)
$$

Big-O는 정확한 실행 시간도, 최악 비용 자체도 아니다. 어떤 함수의 상한인지 명시해야 한다. 평균 실행 시간을 `O(n)`이라고 말할 수도 있고, 최악 실행 시간을 `O(n)`이라고 말할 수도 있다.

### Big-Omega와 Big-Theta

`Ω(g(n))`은 하한이고, `Θ(g(n))`은 상한과 하한이 같은 증가율임을 뜻한다.

대표적인 하한 예가 비교 기반 정렬의 최악 `Ω(n log n)` 비교다. 이 하한의 결정 트리 유도(순열 `n!`개를 구분하려면 트리 높이가 `log2(n!) = Θ(n log n)` 이상)와 Stirling 양측 경계는 여기서 다시 전개하지 않고 결과만 인용한다. 분석에서 중요한 점은 이 하한이 정렬 문제 자체의 절대 한계가 아니라 "비교만으로 분기한다"는 연산 모델의 전제에 묶여 있다는 사실이다. 정수 키의 범위가 제한되어 키를 주소로 직접 쓸 수 있으면 counting sort처럼 이 하한 밖에서 동작한다. 즉 하한은 문제가 아니라 채택한 모델의 성질이다.

### 숨겨진 상수와 교차점

두 알고리즘의 시간 모델이 다음과 같다고 하자.

$$
T_A(n)=8n\log_2 n,\qquad T_B(n)=n^2
$$

점근적으로는 `A`가 더 느리게 증가하지만, $n\ge 2$에서의 교차점은 약 $n=43.6$이다. 그보다 작은 구간에서는 상수가 작은 이차 알고리즘 `B`가 더 빠를 수 있다. 실제 라이브러리가 작은 구간에 insertion sort를 사용하는 것도 이처럼 점근 차수만으로는 결정되지 않는 교차점 문제다. 여기의 계수는 원리를 보이기 위한 예시이며 실제 교차점은 구현과 하드웨어에서 측정해야 한다.

점근 분석은 “언젠가 어느 증가율이 지배하는가”를 말하고, 벤치마크는 실제 입력 범위의 교차점을 찾는다.

## 3. 최악·평균·상각 비용

### 최악 비용

최악 비용은 허용 입력 중 가장 비싼 경우다. 프레임 마감이 있는 시스템에서는 평균이 좋아도 최악 burst가 문제를 만든다.

Hash table 탐색은 평균 `O(1)`이지만 충돌이 한 bucket에 몰리면 최악 `O(n)`이다. 공격자가 키를 선택할 수 있다면 평균 가정이 깨질 수 있다.

### 평균 비용

평균 분석은 입력 분포를 전제로 한다.

$$
\mathbb{E}[T(X)] = \sum_x P(X=x)T(x)
$$

“평균 `O(1)`”이라는 말에는 hash가 충분히 균등하고 load factor가 제한되며 입력이 적대적이지 않다는 전제가 숨어 있다. 실제 workload의 분포가 바뀌면 평균 분석도 바뀐다.

### 상각 비용

상각 분석은 한 연산의 확률 평균이 아니라, 연산 시퀀스 전체 비용을 연산 수에 나눈다.

`vector::push_back`은 capacity가 찰 때 기존 원소를 복사하므로 한 번은 `O(n)`이다. capacity를 두 배로 늘리면 `m`번 push 동안 복사되는 원소 수는 다음처럼 제한된다.

$$
1+2+4+\cdots+2^k < 2m
$$

따라서 전체 비용은 `O(m)`이고 push 하나의 상각 비용은 `O(1)`이다.

상각 `O(1)`은 개별 연산의 latency 상한을 보장하지 않는다. 프레임 안에서 재할당 spike가 문제라면 `reserve`, 고정 capacity, 점진 migration 같은 정책이 필요하다.

### 회계법과 잠재 함수

회계법은 싼 연산에 추가 비용을 부과해 미래의 비싼 연산 비용을 미리 적립한다고 본다. 잠재 함수법은 자료구조 상태에 저장된 “미래 작업량”을 수치로 표현한다.

실제 비용 `c_i`, 상태 잠재량 `Φ(D_i)`에 대해 상각 비용은 다음이다.

$$
\hat c_i = c_i + \Phi(D_i)-\Phi(D_{i-1})
$$

초기 잠재량이 0이고 잠재량이 음수가 아니면, 상각 비용 합은 실제 비용 합의 상한이다.

## 4. 정확성 증명

빠른 알고리즘이 잘못된 답을 내면 의미가 없다. 정확성은 입력 전제 아래 결과가 명세를 만족함을 보이는 일이다.

### 루프 불변식

Insertion sort의 바깥 루프를 보자.

```cpp
for (size_t i = 1; i < a.size(); ++i) {
    int key = a[i];
    size_t j = i;
    while (j > 0 && a[j - 1] > key) {
        a[j] = a[j - 1];
        --j;
    }
    a[j] = key;
}
```

불변식은 “각 반복 시작 시 `a[0..i)`가 정렬되어 있고 원래 해당 구간 원소의 순열이다”이다.

1. 초기화: `i=1`일 때 원소 하나의 구간은 정렬되어 있다.
2. 유지: `key`보다 큰 원소를 한 칸씩 밀고 올바른 위치에 넣으면 `a[0..i+1)`가 정렬된다.
3. 종료: `i == n`이면 전체 배열이 정렬되어 있다.

정렬 여부만 증명하면 원소를 잃거나 복제하는 잘못된 알고리즘도 통과할 수 있다. 순열 보존까지 불변식에 포함해야 한다.

### 귀류법과 교환 논증

Greedy 알고리즘의 정확성에는 교환 논증이 자주 사용된다. 최적해가 탐욕 선택을 포함하지 않는다고 가정하고, 그 일부를 탐욕 선택으로 교체해도 품질이 나빠지지 않음을 보인다. 모든 탐욕법에 이런 증명이 가능한 것은 아니다.

### 반례

증명할 수 없는 규칙은 작은 반례를 찾아야 한다. 예컨대 “항상 가장 큰 단위부터 거슬러 준다”는 탐욕 규칙은 동전 집합 $\{1,3,4\}$로 6을 만들 때 깨진다. 탐욕은 $4+1+1$로 동전 3개를 쓰지만 최적은 $3+3$으로 2개다. 마찬가지로 “현재 가장 가까운 목표부터 방문하면 전체 이동 거리가 최소”라는 규칙도 traveling salesman 문제에서 쉽게 깨진다. 반례는 한 사례만으로 규칙을 무너뜨리기에 충분하며, 작은 완전 탐색으로 탐욕 결과와 최적해를 비교하면 반례를 자동으로 탐색할 수 있다.

## 5. 재귀 알고리즘과 점화식

재귀 알고리즘 비용은 점화식으로 표현한다. 점화식 자체는 답이 아니라 비용의 구조를 적은 것이며, 닫힌 형태의 증가율은 재귀 트리 합산이나 Master 정리 같은 도구로 풀어야 한다.

### 재귀 트리로 비용 합산하기

Merge sort는 배열을 두 부분으로 나누고 각 부분을 정렬한 뒤 선형 시간에 병합한다. 병합 비용 상수를 `c`라 하면 점화식은 다음과 같다.

$$
T(n)=2T(n/2)+cn,\qquad T(1)=\Theta(1)
$$

재귀 트리를 펼치면 깊이 $i$에는 크기 $n/2^i$인 부분 문제가 $2^i$개 있고, 각 노드의 병합 비용은 $c\,n/2^i$이다. 따라서 한 깊이의 전체 비용은 노드 수와 노드 비용의 곱으로 상쇄되어 다음처럼 깊이와 무관하게 일정하다.

$$
2^i \cdot c\,\frac{n}{2^i} = cn
$$

트리의 깊이는 $n$을 1까지 반으로 줄이는 횟수이므로 $\log_2 n$이고, 잎까지 포함한 층 수는 $\log_2 n + 1$이다. 전체 비용은 각 층 비용의 합이다.

$$
T(n)=\sum_{i=0}^{\log_2 n} cn = cn\,(\log_2 n + 1)=\Theta(n\log n)
$$

여기서 핵심은 "층마다 비용이 같다"는 균형이다. 만약 층 비용이 위에서 아래로 기하적으로 커지면 잎(가장 깊은 층)이, 작아지면 뿌리(가장 얕은 층)가 전체 비용을 지배한다. 세 가지 경우의 구분이 곧 Master 정리다.

### Master 정리의 세 경우

Master 정리는 $a\ge 1$, $b>1$인 다음 형태의 점화식을 분류한다.

$$
T(n)=aT(n/b)+f(n)
$$

기준은 잎이 만드는 비용 $n^{\log_b a}$(부분 문제 수의 누적)과 한 단계의 분할·결합 비용 $f(n)$의 대소다.

- 경우 1 (잎 지배): 어떤 상수 $\varepsilon>0$에 대해 $f(n)=O(n^{\log_b a-\varepsilon})$이면 $T(n)=\Theta(n^{\log_b a})$. 비용이 아래로 갈수록 커져 잎이 지배한다.
- 경우 2 (균형): 어떤 정수 $k\ge 0$에 대해 $f(n)=\Theta(n^{\log_b a}\log^k n)$이면 $T(n)=\Theta(n^{\log_b a}\log^{k+1} n)$. 층 비용이 거의 일정해 로그 인수 하나가 붙는다.
- 경우 3 (뿌리 지배): 어떤 상수 $\varepsilon>0$에 대해 $f(n)=\Omega(n^{\log_b a+\varepsilon})$이고, 정칙성 조건 $a\,f(n/b)\le c\,f(n)$이 어떤 $c<1$에서 충분히 큰 $n$에 성립하면 $T(n)=\Theta(f(n))$. 비용이 위에서 지배한다.

Merge sort는 $a=b=2$라 $n^{\log_2 2}=n$이고 $f(n)=\Theta(n)=\Theta(n\log^0 n)$이므로 경우 2($k=0$)에 해당해 $T(n)=\Theta(n\log n)$으로, 재귀 트리 결과와 일치한다. 이진 탐색 $T(n)=T(n/2)+\Theta(1)$은 $n^{\log_2 1}=1$, $f=\Theta(1)$이라 경우 2로 $\Theta(\log n)$이다. Strassen 행렬 곱 $T(n)=7T(n/2)+\Theta(n^2)$은 $n^{\log_2 7}\approx n^{2.807}$이 $f=n^2$보다 다항적으로 크므로 경우 1로 $\Theta(n^{\log_2 7})$이다.

### 정리가 닿지 않는 틈

세 경우는 전부를 덮지 않는다. 경우 1과 2 사이, 2와 3 사이에는 $f$가 $n^{\log_b a}$와 "다항적으로는" 차이 나지 않는(작든 크든 로그 인수 차이뿐인) 틈이 있고, 경우 3의 정칙성 조건이 깨지는 점화식도 있다. 대표 예가 다음이다.

$$
T(n)=2T(n/2)+\frac{n}{\log n}
$$

여기서 $f(n)=n/\log n$은 $n^{\log_2 2}=n$보다 작지만, 어떤 $\varepsilon>0$로도 $n^{1-\varepsilon}$ 이하로 눌리지 않아 경우 1에 들지 않고, $n^{\log_b a}\log^k n$($k\ge 0$) 꼴도 아니라 경우 2에도 들지 않는다. 재귀 트리로 직접 합하면 깊이 $i$의 층 비용이 $n/(\log_2 n - i)$이므로

$$
T(n)=\sum_{i=0}^{\log_2 n - 1}\frac{n}{\log_2 n - i}=n\sum_{j=1}^{\log_2 n}\frac{1}{j}=\Theta(n\log\log n)
$$

으로, 조화수 합 때문에 $\Theta(n\log\log n)$이 된다. 이처럼 Master 정리가 닿지 않는 경우와 부분 문제 크기가 불균등한 점화식($T(n)=T(n/3)+T(2n/3)+\Theta(n)$ 등)은 Akra-Bazzi 방법으로 다룬다.

또한 모든 재귀가 $T(n)=aT(n/b)+f(n)$ 형태도 아니다. Quick sort의 분할 크기는 입력과 pivot에 따라 달라진다. 균형 분할이면 `Θ(n log n)`, 한쪽으로 계속 치우치면 점화식이 $T(n)=T(n-1)+\Theta(n)$이 되어 `Θ(n^2)`이다.

### 정확성과 종료

재귀 정확성은 더 작은 입력에 대해 알고리즘이 맞다고 가정하는 귀납 구조와 base case가 필요하다. 귀납 가정이 성립하려면 재귀 호출의 입력이 base case를 향해 엄격히 줄어들어야 한다. base case가 문제를 충분히 줄이지 않거나 재귀 입력이 감소하지 않으면 종료하지 않는다. 예컨대 정수 나눗셈으로 크기를 줄이는 재귀에서 올림 절반 `n - n/2`가 `n=1`에서 다시 1이 되는 경계를 base case로 끊지 않으면 무한 재귀에 빠진다.

## 6. 무작위 알고리즘

무작위성은 입력 분포를 통제하거나 근사 해를 표본화하는 데 사용한다.

### Las Vegas와 Monte Carlo

- Las Vegas 알고리즘: 결과는 항상 정확하고 실행 시간이 확률적이다.
- Monte Carlo 알고리즘: 실행 시간은 제한되지만 결과에 오류 확률이 있다.

무작위 pivot quick sort는 입력 순서와 무관하게 기대 `O(n log n)` 성능을 얻는 Las Vegas 성격의 알고리즘이다. 정렬 결과는 정확하다. 다만 아래 기대 비교 횟수 분석은 키가 서로 다르다는 전제에서 $z_1<z_2<\cdots<z_n$을 세우므로, 동치 키가 많은 입력에서는 동치 키를 한 번에 처리하는 3-way 분할을 전제로 하거나 별도 분석이 필요하다. 2-way 분할로 모든 키가 같은 입력을 처리하면 무작위 pivot으로도 $\Theta(n^2)$가 될 수 있다.

### 무작위 퀵정렬의 기대 비교 횟수

"기대 `O(n log n)`"은 단정이 아니라 지표 확률 변수와 기대값의 선형성으로 유도된다. 정렬된 출력을 $z_1<z_2<\cdots<z_n$이라 하고, 두 원소 $z_i,z_j$가 알고리즘 전체에서 한 번이라도 비교되면 1, 아니면 0인 지표 변수 $X_{ij}$를 정의한다. 퀵정렬에서 두 원소는 한쪽이 pivot일 때만 비교되므로 많아야 한 번 비교된다.

$z_i$와 $z_j$가 비교될 필요충분조건은 구간 $Z_{ij}=\{z_i,z_{i+1},\dots,z_j\}$ 중에서 가장 먼저 pivot으로 뽑힌 원소가 $z_i$ 또는 $z_j$인 경우다. 만약 그 사이의 다른 원소가 먼저 pivot이 되면 $z_i$와 $z_j$는 서로 다른 분할로 갈라져 영영 비교되지 않는다. pivot을 균등 무작위로 고르므로 $Z_{ij}$의 $j-i+1$개 원소는 모두 같은 확률로 먼저 뽑히고, 그중 둘이 끝 원소이므로

$$
\Pr[X_{ij}=1]=\frac{2}{j-i+1}
$$

이다. 전체 비교 횟수 $X=\sum_{i<j}X_{ij}$의 기대값은 기대값의 선형성으로 확률을 더해 얻는다. 간격 $d=j-i$로 묶으면 간격이 $d$인 쌍은 $n-d$개이므로

$$
\mathbb{E}[X]=\sum_{i=1}^{n-1}\sum_{j=i+1}^{n}\frac{2}{j-i+1}=\sum_{d=1}^{n-1}(n-d)\frac{2}{d+1}=2(n+1)H_n-4n
$$

이고, 여기서 $H_n=\sum_{k=1}^{n}1/k=\ln n+\gamma+O(1/n)$은 조화수다. 따라서 $\mathbb{E}[X]=2n\ln n+O(n)=O(n\log n)$이다. 수치로 보면 $n=100$일 때 $H_{100}\approx5.187$이라 기대 비교는 $2\cdot101\cdot5.187-400\approx648$회인 반면, 최악(이미 정렬된 입력에 끝 원소를 pivot으로 고르는 경우)은 $\binom{100}{2}=4950$회로 약 7.6배다.

이 경계의 전제는 pivot 선택의 무작위성이지 입력의 무작위성이 아니다. 적대적으로 구성된 입력이라도 pivot을 매번 균등 무작위로 뽑으면 같은 기대 경계가 성립한다. 다만 이는 어디까지나 기대값이며 드물게 $O(n^2)$ 실행이 남는다. 최악 상한 자체를 없애려면 결정적 median-of-medians로 pivot을 고르거나 introsort처럼 재귀 깊이가 임계를 넘을 때 heap sort로 전환해야 한다.

Bloom filter는 존재하지 않는 원소를 존재한다고 오판할 수 있지만 false negative는 없는 Monte Carlo 자료구조다. bit 수 `m`, hash 수 `k`, 삽입 수 `n`에 따른 false positive 확률은 근사적으로 다음과 같다.

$$
p \approx \left(1-e^{-kn/m}\right)^k
$$

무작위 알고리즘은 기대값뿐 아니라 분산과 tail을 봐야 한다. 실시간 경로에서는 드문 긴 실행이 문제가 될 수 있다.

테스트와 replay를 위해 seed를 기록해야 한다. 고정 seed 하나만 테스트하면 특정 난수 경로만 검증하므로 여러 seed 집합과 실패 seed 회귀를 함께 사용한다.

## 7. 하드웨어 비용 모델

같은 `O(n)`이라도 메모리 접근 방식이 다르면 실행 시간이 크게 다르다.

```cpp
for (const Item& x : contiguousVector) Process(x);
for (Node* p = head; p; p = p->next) Process(p->value);
```

연속 배열은 hardware prefetch와 캐시 라인을 활용한다. 연결 리스트는 각 노드 접근이 다음 주소를 알아야 하고 메모리에 흩어져 있어 latency를 겹치기 어렵다.

알고리즘 비용 모델에는 다음을 추가해야 한다.

- 읽고 쓰는 바이트 수
- 접근의 연속성과 재사용
- 할당·해제 횟수
- 분기 예측 가능성
- SIMD 가능성
- thread 간 통신과 동기화
- 디스크·네트워크 I/O 횟수

외부 메모리에서는 CPU 연산보다 블록 전송 횟수가 중요하다. 데이터가 RAM에 들어오지 않는 정렬은 chunk별 정렬 후 다중 병합하는 external merge sort가 자연스럽다.

병렬 알고리즘에서는 전체 work와 의존성의 가장 긴 경로 span을 구분한다. 프로세서가 많아도 실행 시간은 span보다 짧아질 수 없다.

## 8. 알고리즘 엔지니어링 절차

### 기준 구현

먼저 느리더라도 단순하고 검증 가능한 기준 구현을 둔다. 빠른 공간 질의는 brute force 결과와 비교하고, 복잡한 충돌 알고리즘은 작은 정확 구현과 비교한다.

### 대표 입력과 적대 입력

입력 크기 하나로는 부족하다.

```text
크기 분포
정렬 정도
중복률
공간 밀도와 군집
업데이트·질의 비율
최악 burst
신뢰할 수 없는 입력
```

실제 플레이 캡처와 합성 경계 입력을 함께 사용한다.

### 벤치마크

컴파일러가 결과를 제거하지 못하게 하고, release 옵션과 실제 플랫폼에서 측정한다. 워밍업, CPU 주파수, background 작업, 메모리 할당 상태를 통제한다.

평균만 보지 않고 P50·P95·P99, 최대값, 메모리 peak, 할당 횟수를 기록한다. 실시간 경로에서는 상각 평균보다 spike가 중요할 수 있다.

### 선택형 알고리즘

하나의 알고리즘으로 모든 입력을 처리할 필요는 없다.

```text
작은 배열: insertion sort
큰 일반 배열: introsort
제한된 정수 키: radix/counting 계열
```

전환 임계값은 플랫폼별 측정으로 정한다. 미세한 분기를 너무 많이 추가하면 유지보수와 코드 캐시 비용이 커진다.

### 회귀 검증

성능 변경은 출력 정확성과 성능을 함께 비교한다. 절대 시간은 머신 노이즈에 민감하므로 기준 구현 대비 비율과 구조적 지표도 저장한다.


## 9. 정확성의 대상

명세는 프로그램이 외부에서 관측 가능한 동작을 정의한다. 구현은 명세를 만족하는 여러 방법 중 하나다. 명세가 내부 자료구조와 함수 호출 순서까지 강제하면 더 나은 구현으로 교체하기 어렵고, 반대로 “올바른 결과를 반환한다”처럼 결과를 정의하지 않으면 검증할 수 없다.

정확성은 보통 세 층으로 나뉜다.

| 층 | 질문 | 예 |
|---|---|---|
| 기능 정확성 | 결과 값이 맞는가 | 최단 경로 비용이 실제 최솟값인가 |
| 상태 정확성 | 연산 후 허용 상태인가 | free list와 사용 중 슬롯이 겹치지 않는가 |
| 시간·운영 정확성 | 정해진 조건 안에서 결과가 오는가 | 요청이 timeout 안에 성공하거나 실패로 끝나는가 |

총 함수는 모든 입력에 결과를 정의한다. 부분 함수는 특정 사전조건 아래에서만 의미가 있다. 배열 인덱스 접근이 `0 <= i < size`를 요구하는 것이 대표적이다. 부분 함수를 총 함수처럼 사용하면 “잘못된 입력의 결과”가 구현 세부나 미정의 동작에 맡겨진다.

## 10. 사전조건·사후조건·불변식

Hoare triple은 명령의 계약을 다음처럼 표현한다.

$$
\{P\}\ C\ \{Q\}
$$

`P`가 참인 상태에서 명령 `C`가 정상 종료하면 `Q`가 참이라는 뜻이다. `P`는 사전조건, `Q`는 사후조건이다.

예를 들어 빈 공간이 있는 bounded queue의 push는 다음 계약을 가질 수 있다.

```text
사전조건:
  0 <= count < capacity

연산:
  Push(x)

사후조건:
  count' = count + 1
  Back(queue') = x
  기존 원소의 상대 순서가 유지됨
```

불변식은 외부에 공개된 모든 허용 상태에서 참이어야 하는 조건이다.

```text
0 <= count <= capacity
head < capacity
tail < capacity
count == 0  => head == tail
count == capacity => head == tail
```

마지막 두 조건은 `head == tail`만으로 empty와 full을 구분할 수 없다는 사실도 드러낸다. 불변식을 적으면 구현에 필요한 추가 상태 `count` 또는 한 칸 비우기 규칙이 자연스럽게 나온다.

사전조건과 외부 입력 검증을 구분해야 한다. 모듈 내부에서 이미 검증된 값만 받는 함수는 사전조건 위반을 프로그래머 오류로 보고 assert할 수 있다. 네트워크 패킷과 파일처럼 신뢰할 수 없는 입력은 release 빌드에서도 항상 검증하고 안전하게 실패해야 한다.

## 11. 상태 기계와 전이 계약

시간에 따라 동작하는 시스템은 상태 기계로 표현할 수 있다. 연결 프로토콜을 예로 들면 다음 상태가 있을 수 있다.

```text
Disconnected
Connecting
Authenticated
Closing
```

각 입력은 모든 상태에서 같은 의미를 갖지 않는다. `GameplayPacket`은 `Authenticated`에서만 허용되고, `AuthResponse`가 `Disconnected`에서 오면 낡거나 위조된 입력이다.

전이 계약은 현재 상태, 입력, 다음 상태, 부수 효과를 함께 정의한다.

| 현재 | 입력 | 다음 | 효과 |
|---|---|---|---|
| Connecting | AuthSuccess | Authenticated | session key 설치 |
| Connecting | Timeout | Disconnected | 임시 상태 폐기 |
| Authenticated | Disconnect | Closing | 종료 알림 전송 |

상태를 여러 bool로 표현하면 불가능한 조합이 생기기 쉽다.

```cpp
bool connected;
bool authenticated;
bool closing;
```

`connected == false`, `authenticated == true` 같은 모순 상태가 타입상 가능하다. 명시적 enum과 상태별 데이터 구조는 불가능 상태를 줄인다.

분산 환경에서는 입력 중복과 재정렬을 전이 모델에 넣어야 한다. 같은 `Commit` 메시지가 두 번 와도 결과가 한 번만 적용되어야 하고, 더 낮은 세대의 메시지는 현재 상태를 되돌리지 못해야 한다.

## 12. 안전성과 활성

안전성은 “나쁜 일이 일어나지 않는다”는 속성이다.

- 잔액 합계가 생성·소멸 규칙 없이 변하지 않는다.
- 두 플레이어가 같은 독점 아이템을 동시에 소유하지 않는다.
- 해제된 handle이 새 객체를 가리키지 않는다.

활성은 “좋은 일이 결국 일어난다”는 속성이다.

- 큐에 들어간 작업이 결국 처리되거나 명시적으로 취소된다.
- 연결 요청이 성공하거나 timeout으로 끝난다.
- 락을 기다리는 스레드가 영원히 굶지 않는다.

안전성은 유한한 반례로 깨진다. 잘못된 상태 하나를 찾으면 된다. 활성 위반은 무한히 기다리는 실행이므로 환경 전제가 필요하다. 메시지가 결국 전달되고 scheduler가 준비된 작업을 영원히 무시하지 않는다는 공정성 가정 없이 “언젠가 처리된다”를 보장할 수 없다.

실무에서는 활성을 bounded property로 바꾸면 검증하기 쉽다.

```text
요청은 2초 안에 성공 또는 실패 응답으로 끝난다.
ready 작업은 5프레임 안에 최소 한 번 실행된다.
```

## 13. 타입으로 불가능 상태 제거

런타임 검증이 필요한 조건도 있지만, 일부 불변식은 타입으로 옮길 수 있다.

```cpp
struct PlayerId { uint64_t value; };
struct ServerTick { uint32_t value; };
struct Meters { float value; };
```

세 타입이 모두 숫자라도 서로 암시적으로 섞이지 않으면 단위와 의미 오류를 막을 수 있다.

검증 전·후 값을 다른 타입으로 표현하는 것도 유용하다.

```cpp
struct RawToken { std::string bytes; };
struct VerifiedSession { SessionId id; Permissions permissions; };

std::optional<VerifiedSession> Verify(const RawToken&);
```

`VerifiedSession`을 가진 함수는 토큰 검증을 다시 수행할 필요가 없다. 다만 이렇게 검증 경계를 타입 생성 함수 하나로 모으려면 멤버를 공개한 위 구조만으로는 부족하다. 아무 호출자나 직접 만들 수 있으므로, 타입 자체로 `Verify`에서만 생성됨을 강제하려면 생성자를 private으로 두고 제한된 factory만 공개해야 한다. 교육용 표시 타입으로 남겨 둔다면 신뢰된 호출자 규약임을 명시하고, 인증 시점에 부여된 권한과 질의 시점에 다시 확인해야 할 현재 권한이 다르다는 점도 구분해야 한다.

타입이 모든 동적 속성을 표현할 수는 없다. “이 handle은 현재 세대에서 유효하다”는 런타임 상태에 의존한다. 타입은 자주 깨지고 비용이 큰 불변식에 집중하고, 나머지는 assert·검증·테스트로 보완해야 한다.

## 14. 명세의 실패 방식

명세도 틀릴 수 있다.

### 환경보다 강한 가정

UDP 위 프로토콜이 메시지 순서를 보장한다고 가정하면 구현 검증은 현실을 보호하지 못한다. 채널이 손실·중복·재정렬을 허용한다면 모델도 이를 포함해야 한다.

### 측정할 수 없는 표현

“빠르게 처리한다”는 명세가 아니다. 입력 크기, 플랫폼, 분위수, deadline을 정해야 한다.

```text
32명 매치의 권위 tick은 기준 서버에서 P99 12ms 이하로 완료한다.
```

### 구현을 그대로 복사한 모델

모델과 구현이 같은 실수를 공유하면 검증이 독립적인 oracle이 되지 못한다. 명세는 더 단순하고 독립적인 표현을 사용해야 한다.

### 예외 경로 누락

성공 경로만 명세하면 취소, timeout, 중복, 재시작에서 자원과 상태가 새어 나간다. 실패 뒤 상태 보장도 사후조건이다.

## 15. 실무 검증 절차

1. 실패 비용이 큰 불변식을 한 문장으로 쓴다.
2. 그 보장이 성립하는 환경 전제를 쓴다.
3. 상태와 허용 전이를 최소 모델로 표현한다.
4. 정상·경계·실패 입력에서 불변식이 유지되는지 확인한다.
5. 불변식을 assert, property test, 운영 지표로 반복 표현한다.
6. 코드 변경 시 관련 명세와 검증도 함께 리뷰한다.

예를 들어 거래 시스템의 핵심 불변식은 다음처럼 시작할 수 있다.

```text
보존:
  거래 전후 두 계정이 소유한 대상 아이템의 총수는 같다.

독점:
  어느 시점에도 하나의 아이템 인스턴스는 최대 한 계정에 속한다.

종료:
  승인된 거래는 deadline 안에 Commit 또는 Abort로 끝난다.
```

이 세 문장은 데이터베이스 제약, 상태 기계, 중복 제거, timeout, 감사 로그의 설계를 이끈다.

## 16. 계산 가능성과 계산 복잡도의 경계

점근 분석은 이미 선택한 알고리즘의 비용을 설명한다. 복잡도 이론은 한 단계 더 내려가 **그 문제 자체를 얼마나 효율적으로 풀 수 있는가**를 묻는다. 이 구분이 없으면 지수시간 탐색을 미세 최적화하며 다항시간 해법을 찾고 있다고 착각하거나, 반대로 작은 입력에서 충분히 풀 수 있는 문제를 “NP라 불가능하다”고 포기하게 된다.

### 결정·탐색·최적화 문제를 구분한다

같은 도메인 문제도 질문의 형태가 다르다.

```text
결정:
  비용 B 이하의 경로가 존재하는가?

탐색:
  그런 경로 하나를 반환하라.

최적화:
  가능한 경로 중 비용이 최소인 것을 반환하라.
```

복잡도 클래스는 주로 예/아니오로 답하는 결정 문제를 기준으로 정의한다. 탐색·최적화 문제도 임계값을 둔 결정 문제로 연결할 수 있다. 예를 들어 최적 비용이 정수 범위 $[0,U]$에 있으면 “비용 $B$ 이하 해가 존재하는가?”를 이진 탐색해 최적값을 찾을 수 있다. 다만 결정 oracle이 실제 해의 구성까지 곧바로 주는지는 문제별 자기 환원 구조를 확인해야 한다.

입력 길이를 $n$이라 할 때 **P**는 결정적 알고리즘으로 $n^{O(1)}$ 시간에 풀 수 있는 결정 문제의 집합이다. 지수가 100인 다항식이 실용적이라는 뜻은 아니다. P는 입력이 커질 때 지수 폭발을 피한다는 이론적 경계다.

**NP**는 YES 인스턴스에 대해 길이 $\mathrm{poly}(n)$인 *증명서(certificate)*가 존재하고, 주어진 증명서로 답이 맞는지 다항시간에 검증할 수 있는 결정 문제의 집합이다. 즉 “답이 예”인 경우에만 짧은 증명서가 보장되며, NO 인스턴스에도 짧은 인증서가 있어야 한다는 것은 일반적인 NP의 정의가 아니다. NP는 “비결정적 다항시간”의 약자이지 “non-polynomial”의 약자가 아니다.

```text
문제:
  그래프에 길이 K 이상의 단순 경로가 존재하는가?

증명서:
  정점 K+1개가 나열된 경로(간선 K개)

검증:
  정점 중복이 없는지, 연속한 정점마다 간선이 있는지 O(K + E_lookup)에 확인
```

해를 찾는 일은 어려워 보여도 후보 검증은 쉽다. 모든 P 문제는 계산한 답을 그대로 검증할 수 있으므로 $P \subseteq NP$다. $P=NP$인지는 알려지지 않았다.

### 다항시간 환원은 어려움을 운반한다

문제 $A$의 입력을 다항시간에 문제 $B$의 입력으로 바꾸고 답을 보존할 수 있으면

$$
A \le_p B
$$

라고 쓴다. 이때 $B$를 빠르게 풀 수 있다면 변환 전후 비용을 합쳐 $A$도 빠르게 풀 수 있다. 따라서 **$A$가 이미 어렵다는 것을 알고 $A \le_p B$를 보이면 $B$도 적어도 그만큼 어렵다**.

환원의 방향을 뒤집는 실수가 흔하다. $B \le_p A$는 $A$를 이용해 $B$를 푼다는 뜻이므로, $B$의 난해성을 증명하지 않는다. 새 문제 $X$의 NP-난해성을 보이려면 알려진 NP-난해 문제 $H$에서 출발해 $H \le_p X$를 구성해야 한다.

**NP-난해(NP-hard)** 문제는 모든 NP 문제의 어려움을 받아낼 만큼 어렵다. 그 문제 자체가 NP에 속할 필요는 없고 결정 문제일 필요도 없다. **NP-완전(NP-complete)** 문제는 NP에 속하면서 NP-난해한 결정 문제다.

NP-완전성 증명의 골격은 두 부분이다.

1. 후보 해를 다항시간에 검증할 수 있음을 보여 $X \in NP$를 증명한다.
2. 알려진 NP-완전 문제 $H$의 임의 입력을 $X$ 입력으로 다항시간에 바꾸고 예/아니오가 보존됨을 양방향으로 증명한다.

### 3-SAT에서 Independent Set으로

환원이 단순한 이름 바꾸기가 아니라 해 구조의 보존임을 한 예로 확인하자. 3-CNF 식이 $m$개 절을 가지고 각 절에 리터럴 세 개가 있다고 하자.

1. 각 절마다 리터럴 세 개를 정점으로 하는 삼각형을 만든다.
2. 서로 다른 절에 있는 두 리터럴이 $x$와 $\neg x$처럼 모순이면 두 정점을 간선으로 잇는다.
3. 크기 $m$의 독립 집합이 있는지 묻는다.

각 절의 세 정점은 삼각형이므로 독립 집합은 절마다 최대 한 정점만 고를 수 있다. 크기가 $m$이면 모든 절에서 정확히 하나를 골랐다. 모순 리터럴끼리도 간선으로 연결했으므로 선택된 리터럴들은 동시에 참이 될 수 있고, 원래 식을 만족한다.

반대로 식을 만족하는 할당이 있으면 각 절에서 참인 리터럴 하나를 고른다. 같은 절의 두 정점을 고르지 않고 서로 모순인 리터럴도 고르지 않으므로 크기 $m$의 독립 집합이다. 변환이 식 크기의 다항식 안에서 끝나므로

$$
3\text{-SAT} \le_p \text{Independent Set}
$$

이다. Independent Set 후보는 정점 수와 모든 내부 간선을 검사해 다항시간에 검증할 수 있으므로 NP에 속하고, 이 환원으로 NP-완전하다.

증명의 핵심은 “SAT도 어렵고 그래프 문제도 어려워 보인다”가 아니다. 만족 할당과 크기 $m$ 독립 집합 사이의 대응을 양방향으로 보인 것이다.

### NP-난해가 실무에서 뜻하는 것

NP-난해라는 분류는 “어떤 입력도 풀 수 없다”가 아니다. 다음 조건이 바뀌면 실용 해법이 생긴다.

| 손잡이 | 의미 | 예 |
|---|---|---|
| 입력 크기 제한 | $2^n$도 $n=20$이면 가능할 수 있음 | 소수 유닛의 전술 배치 |
| 매개변수화 | 전체 크기보다 작은 매개변수 $k$에 지수 비용 집중 | 장애물 수·분대 수가 작은 탐색 |
| 근사 | 최적값 대신 보장된 비율의 해 | metric TSP의 근사 |
| 완화 | 정수·논리 제약을 연속 문제로 낮춰 하한 획득 | 스케줄링의 LP relaxation |
| 휴리스틱 | 보장은 약하지만 시간 예산 안에 좋은 해 탐색 | 로컬 탐색·beam search |
| 전처리 | 지배되는 선택과 불가능 상태 제거 | constraint propagation |
| anytime | 시간이 늘수록 해를 개선하고 언제든 중단 | branch-and-bound |

게임에서는 입력 분포와 프레임 마감이 명세의 일부다. 에디터의 오프라인 배치 문제는 수분 동안 exact solver를 돌릴 수 있지만, 프레임 안의 AI 계획은 제한된 노드만 확장하고 현재 최선의 해를 반환해야 한다. “NP-난해”는 알고리즘 이름이 아니라 **정확성·최적성·입력 크기·시간 예산 중 무엇을 완화할지 결정하라는 신호**다.

평균적으로 잘 풀린다는 사실과 최악 복잡도도 분리해야 한다. SAT solver는 산업의 큰 식을 자주 풀지만 적대적 식에서 지수적으로 폭발할 수 있다. 운영 계약에는 노드·시간·메모리 상한과 timeout 뒤 반환할 품질을 넣어야 한다.

### 의사다항시간과 입력 인코딩

숫자 값 $W$에 비례하는 $O(nW)$ 알고리즘은 입력 길이에 대해 다항시간이라고 바로 말할 수 없다. $W$를 이진수로 쓰는 데 필요한 비트 수는 $\log W$이므로, $W$ 자체에 선형인 시간은 입력 비트 수에 대해 지수적일 수 있다. 배낭 문제의 전형적인 DP가 $O(nW)$인 이유로 **의사다항시간(pseudo-polynomial)**이라 불린다.

게임 데이터에서 능력치·예산 상한을 작게 고정하면 이 알고리즘은 매우 실용적이다. 그러나 “정수이므로 DP가 다항시간”이라는 결론은 입력 값과 입력 인코딩 길이를 섞은 것이다.

### 결정 불가능성은 더 강한 경계다

NP-완전 문제는 답을 계산하는 알고리즘이 존재하며, 유한 입력에서는 완전 탐색으로 결국 끝난다. **결정 불가능(undecidable)** 문제는 모든 입력에 대해 멈추며 정확히 답하는 알고리즘 자체가 없다.

대표가 정지 문제다.

```text
Halts(program, input):
  program이 input에서 언젠가 종료하면 true,
  영원히 실행하면 false를 반환한다고 가정한다.
```

그런 `Halts`가 있다고 가정하고 다음 프로그램을 만든다.

```text
Contradict(p):
  if Halts(p, p):
      loop forever
  else:
      return
```

`Contradict(Contradict)`를 생각하면 모순이다. `Halts`가 종료한다고 답하면 프로그램은 영원히 돌고, 종료하지 않는다고 답하면 즉시 끝난다. 따라서 임의의 프로그램과 입력에 대해 정지를 완벽히 판정하는 총 알고리즘은 존재하지 않는다.

이 결과가 정적 분석·컴파일러·스크립트 검증이 무의미하다는 뜻은 아니다. 분석기는 언어를 제한하거나, 일부 경우에 `unknown`을 반환하거나, 거짓 양성·거짓 음성 중 하나를 허용해 유용해진다. 에디터가 사용자 스크립트의 무한 루프를 완벽히 찾아낼 수는 없지만 명령 수 예산, 협력적 yield, 격리 프로세스, watchdog으로 제품의 종료 성질을 강제할 수 있다.

복잡도와 결정 가능성은 최적화 이전의 설계 입력이다. 다항시간 문제는 비용 모델을 개선하고, NP-난해 문제는 제한·근사·예산을 계약하며, 결정 불가능한 속성은 언어와 실행 환경을 제한해 다룬다.

---

## 결론

알고리즘 분석은 Big-O 한 줄로 끝나지 않는다. 입력과 출력, 정확성, 비용 단위를 먼저 정의하고, 점근 분석으로 증가율을 설명하며, 최악·평균·상각 비용의 전제를 구분해야 한다. 루프 불변식과 귀납·교환 논증은 결과가 옳은 이유를 설명하고, 반례 탐색은 근거 없는 직관을 깨뜨린다. P·NP와 다항시간 환원은 문제 자체의 어려움을 구분하고, 결정 불가능성은 자동 분석이 넘을 수 없는 경계를 정한다.

현대 게임 코드에서는 데이터 이동, 캐시, 할당, 병렬 의존성, 프레임 마감이 실제 비용을 결정한다. 따라서 기준 구현과 대표·적대 입력을 준비하고, 정확성 비교와 재현 가능한 성능 측정을 함께 수행해야 한다. 이론은 측정하지 않은 입력을 설명하고, 측정은 이론의 비용 모델을 현실에 맞게 교정한다.
