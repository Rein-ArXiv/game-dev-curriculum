## 1. 메시: 정점과 인덱스

3D 모델은 *삼각형의 집합* 이고, 그 삼각형들을 표현하는 표준 자료 구조가 *인덱스드 메시(indexed mesh)* 다. 두 배열로 이뤄진다.

- **정점 배열(vertex array)**: 각 정점의 데이터(위치·법선·UV…)를 담은 목록. 중복 없는 *고유 정점* 들.
- **인덱스 배열(index array)**: 정점 배열의 *번호* 로 삼각형을 정의. 3개씩 끊어 한 삼각형.

```text
정점:  [ v0  v1  v2  v3 ]        // 사각형의 네 모서리
인덱스: [ 0,1,2,  0,2,3 ]        // 삼각형 둘 → 사각형
```

왜 둘로 나누는가? *정점 공유* 때문이다. 사각형은 모서리 4개지만 삼각형 2개로 그리려면 정점이 6개 필요하다(삼각형당 3개). 인덱스를 쓰면 *공유되는 모서리 정점을 한 번만 저장* 하고 번호로 재참조한다 — 4개 정점 + 6개 인덱스로 끝난다. 메시가 클수록 이 절약이 커진다. 닫힌 격자 표면에서 정점 하나는 평균 6개 삼각형에 공유되므로, 인덱스 없이 저장하면 데이터가 약 6배로 부푼다.

이것이 프리미티브 토폴로지의 데이터 측면이다. 삼각형 리스트(인덱스 3개씩 독립)가 가장 일반적이고, 스트립(정점을 하나씩 밀며 연쇄)은 인덱스 없이도 정점을 재사용하지만 토폴로지가 제약된다. 실무는 거의 *인덱스드 삼각형 리스트* 를 쓴다 — 유연하면서 정점 공유의 이득을 누린다.

### 숫자로 따라가기

$11\times11$ 정점 격자(지형 한 타일)를 보자. 고유 정점은 $121$개, 삼각형은 $(11{-}1)^2\times2=200$개라 인덱스는 $600$개다. 인덱스를 안 쓰면 삼각형마다 정점 3개를 따로 담아 *정점 인스턴스 $600$개* — 같은 모서리 정점이 여러 번 중복된다. 인덱스를 쓰면 *고유 $121$개* 만 저장·변환하고 $600$개 인덱스(2바이트)로 엮는다. 정점 데이터가 32바이트(위치+법선+UV)라면 비인덱스 $600\times32=19200$바이트 대 인덱스 $121\times32+600\times2=5072$바이트 — 약 *3.8배* 절약이고, 정점 셰이더 변환 횟수는 $600\to121$로 *5배 가까이* 준다(3절의 정점 캐시가 받쳐줄 때). 메시가 클수록 이 비율은 격자의 공유도(정점당 평균 6삼각형)에 수렴한다.


## 2. 정점 속성과 레이아웃

한 정점은 위치 하나만 갖지 않는다. 셰이딩에 필요한 여러 *속성(attribute)* 의 묶음이다.

| 속성 | 용도 | 쓰는 곳 |
|---|---|---|
| 위치(position) | 변환의 입력 | |
| 법선(normal) | 라이팅 | |
| 텍스처 좌표(UV) | 텍스처 샘플링 | |
| 접선(tangent) | 법선 매핑 | 6절 |
| 색(color) | 정점 색 | 보간 |
| 뼈 가중치(bone weights) | 스키닝 | 애니메이션 |

이 속성들을 메모리에 *어떻게 배치* 하느냐가 *레이아웃* 이고, 두 방식이 있다.

**인터리브드(Interleaved, AoS — Array of Structures)**: 한 정점의 모든 속성을 연달아 두고, 정점들을 나열한다.

```text
[ pos0 nrm0 uv0 | pos1 nrm1 uv1 | pos2 nrm2 uv2 | ... ]
```

**분리(Separated, SoA — Structure of Arrays)**: 속성별로 따로 배열을 둔다.

```text
위치: [ pos0 pos1 pos2 ... ]   법선: [ nrm0 nrm1 ... ]   UV: [ uv0 uv1 ... ]
```

선택의 기준은 *접근 패턴* 이다. 정점 셰이더는 한 정점의 *모든 속성을 함께* 읽으므로, 인터리브드가 한 정점 데이터를 *한 캐시 라인* 에 모아 효율적이다 — 일반 렌더링의 기본값이다. 반면 *깊이 전용 패스*(그림자 맵·Z-prepass)처럼 *위치만* 필요한 경우엔, 위치를 별도 스트림으로 분리(SoA)해 두면 법선·UV를 건너뛰고 위치만 촘촘히 읽어 대역폭을 아낀다. 그래서 현대 엔진은 *위치 스트림 + 나머지 속성 스트림* 으로 나누는 절충을 자주 쓴다. API는 이 레이아웃을 *정점 입력 명세*(OpenGL VAO, DirectX Input Layout, Vulkan VertexInputState — 매핑)로 GPU에 알려, 각 속성을 셰이더 입력에 연결한다.


## 3. 인덱스 버퍼와 정점 재사용

인덱스의 이득은 *저장* 만이 아니다. 더 큰 이득은 *계산 재사용* 이다. GPU에는 *후변환 정점 캐시(post-transform vertex cache)* 가 있어, 정점 셰이더가 변환한 결과를 잠시 저장한다. 인덱스가 *방금 처리한 정점* 을 다시 가리키면, 정점 셰이더를 *다시 돌리지 않고* 캐시된 결과를 재사용한다.

이 덕분에 한 정점이 6개 삼각형에 공유돼도 정점 셰이더는 (캐시가 충분하면) 그 정점을 *한 번만* 변환한다. 인덱스 없이 그리면 같은 정점이 6번 변환되어 정점 처리 비용이 6배다. 즉 인덱스는 *정점 처리 단계의 일* 을 직접 줄인다.

후변환 캐시의 구조와 유효 용량은 구현마다 다르므로, *인덱스 순서* 는 특정 고정 크기가 아니라 짧은 재사용 거리를 목표로 최적화한다. 한 정점을 공유하는 삼각형들이 인덱스 배열에서 가까우면 결과가 살아 있는 동안 재사용될 가능성이 높고, 멀리 흩어지면 재변환될 수 있다. 메시 도구는 이를 위해 Forsyth·Tipsify·meshoptimizer 계열 재배열을 빌드 단계에서 수행한다. 정점 처리량은 줄일 수 있지만 인덱스 순서가 공간적 군집·오버드로·meshlet 구성에도 영향을 주므로, “공짜”로 단정하지 말고 목표 장치의 post-transform invocation과 프래그먼트 비용을 함께 측정한다.

> 비유: 밉맵이 텍스처 *읽기* 를 재사용해 대역폭을 아꼈다면, 정점 캐시는 정점 *변환* 을 재사용해 계산을 아낀다 — 둘 다 "이미 한 일을 다시 하지 않기"다.


## 4. 감김 순서

삼각형의 세 정점을 인덱스에 적는 *순서* 는 단순한 나열이 아니라 *방향* 을 담는다. 정점이 화면에서 시계 방향(CW)으로 도느냐 반시계 방향(CCW)으로 도느냐 — *감김 순서(winding order)* — 가 삼각형의 *앞면과 뒷면* 을 정의한다.

```text
   v0          앞면(CCW)을 보는 시점에서
  /  \         v0→v1→v2 가 반시계 방향
 v1——v2        → 이 면이 카메라를 향한 앞면
```

이것이 엣지 함수 부호, 백페이스 컬링과 직결된다. 래스터화기는 삼각형의 화면 공간 *부호 있는 면적*으로 감김을 판정하고, 응용이 지정한 컬 모드에 따라 한쪽 면을 버린다. 닫힌 불투명 메시를 바깥쪽 기준의 일관된 감김으로 만들면 카메라 반대쪽 면을 안정적으로 제거할 수 있다. 제거 비율은 물체 형상과 시점에 따라 달라 정확히 절반이라고 보장할 수 없다.

함정은 *일관성* 이다. 메시 일부의 감김이 뒤집혀 있으면(모델링 도구에서 면을 잘못 뒤집은 경우), 그 부분만 컬링이 거꾸로 동작해 *구멍처럼 뚫려* 보인다. 또 음수 스케일(모델 행렬에 거울 반전이 들어간 경우)은 감김을 뒤집으므로, API의 "앞면 정의"(CW/CCW)를 그에 맞춰 바꾸지 않으면 모델이 *속이 비쳐* 보인다. 감김 순서는 데이터(인덱스)·상태(컬 모드)·변환(스케일 부호) 셋이 맞물리는, 조용하지만 흔한 버그의 원천이다.


## 5. 법선: 면 법선과 정점 법선

모든 라이팅은 표면 법선 $\mathbf{n}$을 요구한다. 그런데 법선은 메시에 *어떻게 저장* 되며, 같은 형상이 *매끄럽게* 도 *각지게* 도 보이는 차이는 어디서 올까?

**면 법선(face normal)**: 삼각형 하나의 법선. 두 모서리 벡터의 외적으로 구한다.

$$
\mathbf{n}_{\text{face}} = \text{normalize}\big( (\mathbf{v}_1 - \mathbf{v}_0) \times (\mathbf{v}_2 - \mathbf{v}_0) \big)
$$

면 전체가 같은 법선을 쓰면 *플랫 셰이딩*처럼 각져 보인다 — 저폴리 미학이나 진짜 평면(상자)에 맞다.

**정점 법선(vertex normal)**: 한 정점을 공유하는 *인접 면 법선들의 평균*. 정점마다 법선을 저장하고, 래스터화가 보간으로 픽셀마다 법선을 매끄럽게 잇는다. 곡면(구·캐릭터)이 부드럽게 보인다 — *퐁 셰이딩* 빈도와 결합되는 것이 이 정점 법선이다.

$$
\mathbf{n}_{\text{vertex}} = \text{normalize}\Big( \sum_{f \ni v} \mathbf{n}_f \Big) \quad (\text{인접 면 법선 합, 면적 가중도 가능})
$$

핵심은 *언제 정점을 쪼개느냐* 다. 상자의 모서리처럼 *진짜로 각진 곳* 은 한 위치에 *법선이 다른 두 정점* 을 둬야(분리) 모서리가 살아난다 — 평균하면 모서리가 뭉개진다. 반대로 매끄러운 곡면은 정점을 공유해 법선을 평균한다. 그래서 모델 도구의 *스무딩 그룹(smoothing group)* / 하드 엣지 설정이 "어느 모서리에서 정점을 쪼갤지"를 정하고, 이것이 메시의 실제 정점 수에 영향을 준다. 그리고 이 법선들은 *역전치 행렬* 로 변환해야 비균등 스케일에서도 표면에 수직을 유지한다는 점을 잊지 말자.


## 6. 접선 공간

법선 맵이 표면 디테일을 지오메트리 없이 흉내 낸다. 그 법선 맵의 값을 쓰려면 메시가 한 가지를 더 제공해야 한다 — *접선 공간(tangent space)* 기저다.

문제의 본질: 법선 맵에 저장된 법선은 *표면에 상대적인* 좌표(접선 공간)다. $(0,0,1)$은 "표면에서 똑바로 바깥"을 뜻한다. 이걸 라이팅에 쓰려면 표면 점마다 *접선 공간 → 월드 공간* 변환이 필요한데, 그 변환 행렬을 세 직교 벡터가 만든다.

- $\mathbf{N}$: 법선(5절). 표면 바깥 방향.
- $\mathbf{T}$: 접선(tangent). 표면을 따라 *UV의 u 축* 이 증가하는 방향.
- $\mathbf{B}$: 종법선(bitangent). 보통 $h(\mathbf{N}\times\mathbf{T})$로 복원하며, $h\in\{-1,+1\}$는 미러 UV가 만드는 기저의 handedness다.

이 $(\mathbf{T}, \mathbf{B}, \mathbf{N})$이 *TBN 행렬* 을 이루고, 법선 맵의 접선 공간 법선을 월드로 옮긴다. 핵심은 $\mathbf{T}$가 *UV 매핑에 의존* 한다는 것 — 텍스처가 어느 방향으로 붙었는지가 접선 방향을 정하므로, 접선은 메시의 위치와 UV로부터 *유도* 된다. 삼각형의 두 모서리와 그에 대응하는 UV 차이로 연립해 푼다.

$$
\begin{cases} \mathbf{e}_1 = \Delta u_1 \mathbf{T} + \Delta v_1 \mathbf{B} \\ \mathbf{e}_2 = \Delta u_2 \mathbf{T} + \Delta v_2 \mathbf{B} \end{cases}
\;\Rightarrow\; \mathbf{T}, \mathbf{B} \text{ 를 } \mathbf{e}_i, \Delta u_i, \Delta v_i \text{ 로 역산}
$$

접선은 보통 메시 빌드 시 정점 속성으로 미리 계산해 저장하거나, 셰이더에서 화면 도함수로 즉석 유도한다. 정점에는 $\mathbf{T}$와 handedness $h$를 저장하고, 변환·보간 뒤 $\mathbf{T}$를 $\mathbf{N}$에 대해 다시 직교화한 다음 $\mathbf{B}=h(\mathbf{N}\times\mathbf{T})$로 만들 수 있다. 단순히 외적만 쓰면 미러 UV 섬에서 법선 맵의 한 축이 뒤집힌다. 에셋 생성기와 셰이더가 MikkTSpace 같은 동일한 접선 기저 규약을 공유해야 bake와 런타임 셰이딩이 일치한다.


## 7. 인스턴싱과 LOD

마지막으로, 같은 메시를 *많이* 그릴 때의 두 기법이다.

**인스턴싱(Instancing)**: 같은 메시(숲의 나무, 군중, 풀잎)를 위치·색만 바꿔 수천 개 그릴 때, 드로우콜을 수천 번 부르면 CPU→GPU 명령 오버헤드가 폭발한다. 인스턴싱은 *한 번의 드로우콜로 N개 사본* 을 그린다 — 정점·인덱스 버퍼는 공유하고, 인스턴스마다 다른 데이터(모델 행렬·색)는 *인스턴스 속성* 으로 별도 스트림에서 공급한다. GPU가 같은 지오메트리를 N번 반복 처리하되 인스턴스 데이터만 바꿔 끼운다. 대규모 식생·군중 렌더링의 필수 기법이다.

**LOD(Level of Detail)**: 멀리 있는 물체는 화면에서 작아 디테일이 안 보이므로, *거리에 따라 더 단순한 메시* 로 교체한다. 가까이선 10만 폴리곤 캐릭터, 멀리선 1천 폴리곤 버전. 밉맵이 *텍스처* 의 거리 기반 LOD였다면, 메시 LOD는 *지오메트리* 의 같은 발상이다 — 둘 다 "필요 없는 디테일에 비용을 쓰지 않기". LOD 단계 사이의 *팝핑(갑작스런 전환)* 을 줄이려 디졸브 블렌딩이나 연속적 LOD(메시를 점진적으로 단순화)를 쓰기도 한다. 극단적으로 아주 먼 물체는 메시 대신 *임포스터(impostor)* — 미리 렌더한 텍스처 한 장(빌보드) — 로 대체한다.

두 기법의 공통 철학은 컬링과 같다 — *보이지 않거나 중요하지 않은 것에 비용을 쓰지 않는다*. 컬링이 "안 보이는 걸 버린다"면, LOD는 "덜 보이는 걸 싸게 그린다", 인스턴싱은 "같은 걸 한꺼번에 그린다".



## 8. 지오메트리 증폭이라는 발상

기초 파이프라인에서 정점 처리는 *1:1* 이었다 — 정점 하나가 들어가 변환된 정점 하나가 나왔다. 지오메트리 증폭 단계는 이 비율을 *1:N* 으로 깬다. 적은 입력에서 많은 출력 프리미티브를 만든다.

```mermaid
flowchart LR
    CP[적은 입력<br/>제어점 16개] -->|테셀레이션| MANY[많은 출력<br/>삼각형 수천 개]
    MANY --> RAST[래스터화]
```

세 가지 동기가 있다.

| 동기 | 설명 |
|---|---|
| **대역폭** | 거친 제어점과 변위 자료로 상세 형상을 평가할 수 있어, 워크로드에 따라 정적 고밀도 정점 전송·저장을 줄임 |
| **적응성** | 카메라 거리·화면 크기에 따라 *필요한 곳만* 세분 (가까이 촘촘, 멀리 성기게) |
| **절차적 생성** | 곡면 수학(베지어·스플라인)을 GPU에서 평가해 부드러운 형상 |

핵심은 증폭량을 GPU에서 런타임에 조절할 수 있다는 것이다. CPU가 미리 고해상도 메시를 모두 제출하는 방식과 달리, 하나의 거친 패치에서 필요한 해상도를 평가할 수 있다. fractional partitioning과 연속적인 레벨 함수는 전환을 완화하지만, 테셀레이션 factor가 양자화되는 경계와 displacement 표본 변화 때문에 팝핑이 자동으로 사라지는 것은 아니다. 인접 패치의 edge factor 일치와 시간적으로 안정된 LOD 정책이 함께 필요하다.


## 9. 테셀레이션 파이프라인

*테셀레이션(tessellation)* 은 면을 더 작은 면들로 *세분(subdivide)* 하는 것이다. 하드웨어 테셀레이션은 정점 처리와 래스터화 사이에 세 부분으로 끼어든다.

```mermaid
flowchart LR
    VS[정점 셰이더<br/>제어점 변환] --> HS[헐 셰이더<br/>Hull / TCS]
    HS --> TES[테셀레이터<br/>고정 함수]
    TES --> DS[도메인 셰이더<br/>Domain / TES]
    DS --> RAST[래스터화]
```

- **헐 셰이더(Hull Shader / Tessellation Control)**: 입력은 *패치(patch)* — 곡면을 정의하는 제어점 묶음(예: 베지어 패치 16점). 두 가지를 출력한다: (1) 제어점을 다음 단계로 넘기고, (2) *테셀레이션 레벨* — 이 패치를 얼마나 잘게 쪼갤지 — 를 정한다. 이 레벨 결정이 적응적 테셀레이션의 핵심이다(10절).
- **테셀레이터(Tessellator)**: *고정 함수*. 헐 셰이더가 정한 레벨대로 *추상 패치 공간*(정사각형 또는 삼각형 도메인)을 잘게 나눠, 균일한 격자의 *무게중심/UV 좌표* 들을 뱉는다. 알고리즘을 바꿀 수 없는 고정 회로 — 고정/프로그래머블 분할이 여기서도 적용된다.
- **도메인 셰이더(Domain Shader / Tessellation Evaluation)**: 테셀레이터가 만든 각 좌표에 대해, 제어점과 그 좌표로 *실제 정점 위치를 평가* 한다. 베지어·B-스플라인 같은 곡면 식을 여기서 계산해 매끄러운 표면 위의 점을 만든다.

요약하면 *헐(얼마나 쪼갤지 결정) → 테셀레이터(쪼개기) → 도메인(쪼갠 점의 실제 위치 계산)* 이다. 입력 패치 하나가 도메인 셰이더 호출 수백~수천 번으로 증폭된다. 곡면 수학이 GPU에서 평가되므로, CPU는 제어점 몇 개만 보내면 된다.


## 10. 적응적 테셀레이션과 LOD

테셀레이션의 진짜 힘은 *균일 분할* 이 아니라 *적응 분할* 에 있다. 헐 셰이더가 패치마다 테셀레이션 레벨을 *동적으로* 정할 수 있으므로, 화면에서 중요한 곳에만 디테일을 쏟는다.

흔한 적응 기준:

| 기준 | 더 잘게 쪼개는 경우 |
|---|---|
| 카메라 거리 | 가까운 패치 (멀면 성기게) |
| 화면 공간 크기 | 화면에서 크게 보이는 패치 |
| 실루엣 곡률 | 윤곽선처럼 굴곡이 도드라지는 곳 |
| 디스플레이스먼트 강도 | 높이 변화가 심한 곳(11절) |

이것이 이산 LOD를 *연속 LOD* 로 끌어올린다. 미리 만든 LOD0/LOD1/LOD2를 거리 임계에서 *툭툭 교체* 하면 팝핑이 보이지만, 테셀레이션 레벨을 거리에 따라 *부드럽게* 올리고 내리면 전환이 매끄럽다. 텍스처 밉맵 LOD가 텍스처 디테일을 거리로 조절했듯, 적응적 테셀레이션은 *지오메트리 디테일* 을 같은 철학으로 조절한다.

함정은 *크랙(crack)* 이다. 인접한 두 패치가 공유 모서리에서 서로 다른 테셀레이션 레벨을 쓰면, 모서리의 정점이 어긋나 *틈* 이 벌어진다 — 공유 엣지 문제가 패치 경계에서 재현되는 셈이다. 그래서 헐 셰이더는 *모서리(edge) 테셀레이션 레벨* 을 이웃과 일치시켜야 한다(보통 양쪽 패치가 같은 모서리 레벨에 합의). 모서리 레벨과 내부(inner) 레벨을 따로 두는 이유가 이 크랙 방지다.


## 11. 디스플레이스먼트 매핑

테셀레이션이 *정점을 만들어 주면*, 그 정점들을 *높이 텍스처로 밀어내* 진짜 굴곡을 만드는 것이 *디스플레이스먼트 매핑(displacement mapping)* 이다. 도메인 셰이더에서 각 새 정점의 UV로 *높이 맵(height map)* 을 샘플링해, 그 값만큼 정점을 법선 방향으로 이동시킨다.

$$
\mathbf{p}' = \mathbf{p} + h(u,v)\cdot \mathbf{n}, \qquad h = \text{texture}(\text{heightMap}, (u,v))
$$

이것이 *법선 매핑* 과 결정적으로 다른 점이다.

| | 법선 매핑 | 디스플레이스먼트 매핑 |
|---|---|---|
| 무엇을 바꾸나 | *법선만* (셰이딩용) | *실제 정점 위치* |
| 실루엣 | 평평함(가짜) | 진짜로 울퉁불퉁 |
| 그림자·가림 | 표면이 평평해 안 맞음 | 자기 그림자·가림 정확 |
| 비용 | 쌈(텍스처 1탭) | 비쌈(테셀레이션 필요) |

법선 맵은 표면을 *평평하게 둔 채 빛 반응만* 속이므로, 윤곽선을 보면 들통난다(벽돌 줄눈이 실루엣에선 매끈). 디스플레이스먼트는 정점을 실제로 밀어내 *실루엣까지 울퉁불퉁* 하고 자기 그림자도 맞는다. 대가는 테셀레이션으로 정점을 충분히 만들어야 한다는 것 — 높이 변화가 큰 곳에 정점이 적으면 계단처럼 보인다(10절의 적응 분할이 이래서 디스플레이스먼트와 짝을 이룬다). 둘을 절충한 *시차 차폐 매핑(parallax occlusion mapping)* 은 정점을 안 늘리고 프래그먼트 셰이더에서 높이 맵을 레이마칭해 *시차만* 흉내 내는데, 실루엣은 여전히 평평하다.


## 12. 지오메트리 셰이더

*지오메트리 셰이더(Geometry Shader)* 는 또 다른 증폭 단계로, *프리미티브 단위* 로 동작한다 — 삼각형(또는 점·선) 하나를 입력받아 *0개 이상의 프리미티브* 를 출력한다. 정점 처리 후, 래스터화 전에 끼어든다.

가능한 일이 독특하다.

- **프리미티브 증폭/제거**: 삼각형 하나에서 여러 개를 뿜거나, 조건에 따라 버린다.
- **프리미티브 전체 정보 접근**: 삼각형 세 정점을 *한꺼번에* 봐서 면 법선·인접성을 계산.
- **레이어드 렌더링**: 한 프리미티브를 여러 렌더 타깃 레이어로 복제 — 큐브맵 6면 그림자를 한 패스에 그리거나, 카메라 6방향을 한 번에.

전통적 용도는 *털·풀 생성*(삼각형마다 잔디 카드 뿜기), *외곽선*, *빌보드 확장*(점 하나를 사각형으로) 등이었다.

지오메트리 셰이더는 가변 출력과 프리미티브 단위 처리 때문에 하드웨어에 따라 처리량이 급격히 낮아질 수 있다. 현대 렌더링은 같은 일을 인스턴싱·컴퓨트 셰이더 또는 workgroup 단위로 정점과 프리미티브를 생성하는 메시 셰이더로 옮기는 경우가 많다. 실제 선택은 목표 GPU의 프로파일로 결정한다.


## 13. 메시 셰이더: 현대적 대안

테셀레이션과 지오메트리 셰이더는 *고정된 파이프라인 단계* 라 유연성에 한계가 있다. 최신 GPU는 지오메트리 처리 앞단을 통째로 *프로그래머블 컴퓨트 모델* 로 갈아엎은 *메시 셰이더(Mesh Shader)* 파이프라인을 제공한다.

```mermaid
flowchart LR
    TS[태스크 셰이더<br/>Task / Amplification] -->|메시렛 디스패치| MS[메시 셰이더<br/>Mesh]
    MS --> RAST[래스터화]
```

발상: 메시를 *메시렛(meshlet)* — 정점 수십·삼각형 수십 개의 작은 덩어리 — 로 미리 쪼개 두고,

- **태스크(증폭) 셰이더**: 어떤 메시렛을 그릴지 정한다. *컬링을 여기서* — 절두체·백페이스·오클루전을 메시렛 단위로 미리 쳐내고, LOD도 고른다.
- **메시 셰이더**: 살아남은 메시렛마다 *컴퓨트 워크그룹처럼* 협력해 정점·프리미티브를 생성한다. 정점 셰이더의 1:1 제약도, 지오메트리 셰이더의 직렬 출력도 없이, 워크그룹이 자유롭게 정점/인덱스를 만든다.

이점은 *세밀한 컬링과 유연성* 이다. 전통 정점 경로보다 앞에서 메시렛 단위 절두체·cone·오클루전 판정을 수행하면, 살아남지 않은 묶음의 정점·프리미티브 출력을 생략할 수 있다. 다만 가상화 지오메트리 시스템이 반드시 메시 셰이더를 쓰는 것은 아니다. compute 기반 가시성·소프트웨어 래스터화·전통 indexed draw를 조합한 구현도 가능하다. 메시 셰이더의 본질은 고전적인 정점 입력·조립 앞단을 workgroup 협력형 생성 모델로 재구성하는 데 있다.

## 결론

지오메트리 처리는 정점을 저장하는 형식과 GPU가 실제로 처리할 프리미티브를 선택·생성하는 과정의 결합이다. 데이터 재사용, LOD, 증폭, 컬링을 함께 설계해야 대역폭과 셰이더 연산을 통제할 수 있다.
