## math/part01_number_representation.md — 확정 6건

> **[2026-08-13 확인] 6건 전부 기반영** — 2026-08-09 배치에서 반영됐고 현재 본문이 정정안대로다.

이 문서는 IEEE754 비트 배치, ULP 표, catastrophic cancellation, Kahan 합산, fast inverse sqrt,
Q16.16 고정소수점을 다룬다. 수치 서술의 밀도가 높고 대부분 정확하지만, **ULP를 두 곳에서
한 binade 잘못 잡았고**, fast inverse sqrt 유도의 마지막 식이 앞 절과 계수가 맞지 않는다.

### 1. L579 — 매직 상수 유도식이 매직 상수를 만들지 못함

```
M = (1 + σ) · 127 · 2²³      (σ ≈ 0.0450465)
```

**대입하면 `0x5f3759df`가 나오지 않는다.**

- 127 · 2²³ = 1,065,353,216
- (1 + 0.0450465) × 1,065,353,216 ≈ **1,113,344,806** ≈ `0x425A_xxxx`
- 그런데 `0x5F3759DF` = **1,597,463,007**

올바른 형태는 **`M = (3/2)(127 − σ)·2²³`** 이다. 재계산:

- (3/2)·2²³ = 12,582,912
- 12,582,912 × (127 − 0.0450465) = 1,598,029,824 − 566,816.5 = **1,597,463,007 = `0x5F3759DF`** ✓ 정확히 일치

문서 자신의 **L569 `I_y ≈ (3/2)·127·2²³ − I_x/2`** 와 **L572 `(3/2)·127·2²³ = 1,598,029,824 = 0x5F400000`**
가 이미 (3/2) 계수를 확립해 놓았는데, L579에서 그 계수가 사라졌다. 즉 문서 내부에서도 어긋난다.
보정의 의미도 "(1+σ)를 곱한다"가 아니라 **"127에서 σ를 빼서 1,598,029,824를 566,817만큼 끌어내린다"** 이다.

### 2. L538 — 보정항의 부호가 반대이고, 애초에 전개가 성립하지 않음

> $\log_2(1+t) \approx t$ … (자세히는 $\log_2(1+t) = t - 0.0860 + O(t^2)$ 같은 보정 가능)

두 가지가 틀렸다.

- **$t \to 0$ 에서 좌변은 0, 우변은 −0.0860.** 상수항이 남으므로 $O(t^2)$ 오차를 가진 전개일 수 없다.
- **부호가 반대다.** $[0,1]$ 에서 $\log_2(1+t) - t \ge 0$ 이고, 미분이 0이 되는 $1+t = 1/\ln 2$
  즉 $t = 0.442695$ 에서 최댓값 $\log_2(1.442695) - 0.442695 = 0.528766 - 0.442695 = **+0.086071**$ 이다.
  0.0860은 "빼는 상수"가 아니라 **근사 오차 $\sigma(t)$의 최댓값(양수)** 이다.

문서 L576이 "근사 $\log_2(1+t) \approx t$ 에는 작은 **음의 편향**이 있어"라고 쓴 것은 이 부호(과소평가)와
정확히 일치한다. 따라서 틀린 것은 L538 괄호 안 수식 하나다.
바르게 쓰면 $\log_2(1+t) = t + \sigma(t),\ 0 \le \sigma(t) \le 0.0861$ 이고,
테일러 전개가 필요하면 $\log_2(1+t) = t/\ln 2 - t^2/(2\ln 2) + O(t^3)$ 이다.

### 3. L315 — `1e6` 근처 ULP가 한 binade 위로 밀림

> `1e6` 끼리는 ULP가 `0.125` 라 `1e-5` 안의 차이는 항상 false

$2^{19} = 524{,}288 \le 10^6 < 1{,}048{,}576 = 2^{20}$ 이므로 지수는 19,
**ULP = $2^{19-23} = 2^{-4} = 0.0625$** 다. `0.125`는 $[2^{20}, 2^{21})$ 구간의 ULP이며,
같은 문서 **L240 표의 "1,048,576 (= 2²⁰) → 0.125" 행**에서 가져온 값으로 보인다.

문서 자신이 **L420에서 "이 크기대(약 $2^{19} \sim 2^{20}$)의 ULP는 `0.0625`"** 라고 정확히 적고 있고,
**L249-253**은 200000에 대해 같은 방법($2^{17} \le 200000 < 2^{18}$ → $2^{-6}$)을 정확히 수행한다.
**내부모순이다.** (결론인 "1e-5 안의 차이는 항상 false"는 0.0625로도 그대로 성립하므로 논지는 무사하다.)

### 4. L766 — 비교표의 float 정밀도(10000 근처)

| 측면 | float (32bit) | Q16.16 |
|---|---|---|
| 정밀도 (1.0 근처) | $1.2 \times 10^{-7}$ | $1.5 \times 10^{-5}$ |
| 정밀도 (10000 근처) | $7.6 \times 10^{-4}$ ← | $1.5 \times 10^{-5}$ |

$2^{13} = 8192 \le 10000 < 16384 = 2^{14}$ 이므로 지수 13,
**ULP $= 2^{13-23} = 2^{-10} = 0.0009765625 \approx 9.8 \times 10^{-4}$**.
$7.6 \times 10^{-4}$ 는 **어떤 binade의 ULP도 아니다**(2의 거듭제곱이 아님).

같은 표의 "1.0 근처 → $1.2 \times 10^{-7}$"는 $2^{-23}$ 로 정확하고, Q16.16 열의
$1.5 \times 10^{-5} = 2^{-16}$ 도 정확하며 두 행에서 같은 값(균일 간격)인 것도 맞다.
이 표에서 틀린 칸은 이 하나다.

### 5. L858 — 거대 좌표 뺄셈의 오차 규모가 약 25배 과장

> 둘 다 (200000, 0, 0) 근처에 있는데 1m 차이 — `a - b` 의 결과가 2cm 단위로 반올림된 값이라
> **1m 차이가 0m 또는 4cm 차이로** 나온다.

문서가 §3.2(L252)에서 스스로 계산한 대로 200000 근처 ULP는 $2^{-6} = 0.015625$(약 1.6cm)다.
그러면:

- 두 좌표의 **저장 오차는 각각 최대 0.5 ULP**, 따라서 차이의 오차는 최대 약 1 ULP ≈ **1.6cm**.
- 뺄셈 자체는 Sterbenz 조건($a/2 \le b \le 2a$)에서 **정확**하다. 여기서 200001과 200000은 조건을 만족한다.
- 실제로 200001.0 / 0.015625 = 12,800,064 이고 200000.0 / 0.015625 = 12,800,000 으로
  **둘 다 격자 위의 정수배라 정확히 표현되고, `a - b`는 정확히 1.0** 이 나온다.

즉 1m 떨어진 두 점의 차는 **1m ± 약 1.6cm** 이지, "0m 또는 4cm"가 될 수 없다.
결과가 0으로 무너지는 것은 **참 차이가 ULP(≈1.6cm)보다 작을 때**다.
현상(거대 좌표에서 거리 계산 정밀도가 무너진다)은 실재하지만 이 문단의 수치가 규모를 과장한다.

> **[반영됨 · 2026-08-13]** 2026-08-09 에 선언부만 `float facing = dot(forward, toEnemy);` 로 고치고 이 지적이 함께 짚은 `dot > …` 중 한 줄이 남아 있었다. 2026-08-13 에 `if (facing > std::cos(radians(30.0f)))` 로 마무리 (현재 `part02_vectors.md` L225). 원 지적 내용은 아래 그대로 보존한다.

```cpp

```

같은 문서 L265 `float d = dot(a, b);`, L468/L496 `float len2 = dot(v, v);`,
L694 `float cosSlope = dot(...)`, L728 `float alignment = dot(...)` 는 모두 이름이 달라 정상이다.
**이 파일에서 이름이 충돌하는 곳은 L220 하나뿐**이고, 이어지는 L222·L225의 `dot > ...` 도 함께 손봐야 한다.

### 1. L673 — 짐벌락 분기의 `atan2` 분모가 항상 0

```cpp
if (std::fabs(sinPitch) > 0.9999f) {
    // 짐벌락 부근 — yaw로 모음, roll = 0
    yaw  = std::atan2(-2.0f * (q.x*q.y - q.w*q.z), 1.0f - 2.0f*(q.y*q.y + q.z*q.z));
```

**분모가 짐벌락에서 정확히 0이 되므로 이 분기는 언제나 0 또는 ±π/2만 돌려준다.**

직접 유도했다. ZYX Tait-Bryan에서 pitch = +90°이면 $R = R_z(y)R_y(90°)R_x(r)$ 이고,

- $R$의 0열 $= R_z(y)R_y(90°)(1,0,0)^T = (0,0,-1)^T$ → **$m_{00} = 0$**
- $R$의 1열 $= R_z(y)(\sin r, \cos r, 0)^T = (\sin(r-y),\ \cos(r-y),\ 0)^T$
  → $m_{01} = \sin(r-y)$, $m_{11} = \cos(r-y)$

쿼터니언→행렬 대응은 $m_{00} = 1-2(y^2+z^2)$, $m_{11} = 1-2(x^2+z^2)$ 이므로,
코드의 분모 `1-2(y²+z²)` 는 곧 $m_{00} = 0$ 이다. **분자는 맞다** — $-2(xy-wz) = -m_{01} = \sin(y-r)$.
따라서 올바른 분모는 **$m_{11} = 1-2(x^2+z^2)$** 이고, 그때
$\operatorname{atan2}(\sin(y-r), \cos(y-r)) = y-r$ 로 roll=0 가정과 맞아떨어진다.

```cpp
yaw = std::atan2(-2.0f*(q.x*q.y - q.w*q.z), 1.0f - 2.0f*(q.x*q.x + q.z*q.z));
```

원인이 분명하다 — **바로 아래 정상 분기(L676-677)의 분모 `1-2(y²+z²)` 를 그대로 복사**하고
분자만 고쳤다. 정상 분기에서는 그 분모가 맞다.

### 1. L393 — 상쇄의 근거로 항진명제를 씀

L393:

> $\vec{a} \cdot \vec{a} = \vec{a} \cdot \vec{a}$ 라 첫 두 항이 상쇄.

인용된 식은 **항진명제**라 아무것도 정당화하지 못한다. 실제로 첫 두 항
$-w(\vec n \cdot \vec v) + w(\vec v \cdot \vec n)$ 이 상쇄되는 근거는
**내적의 교환법칙 $\vec a \cdot \vec b = \vec b \cdot \vec a$** 다.
서로 다른 두 벡터가 들어갈 자리에 같은 벡터를 두 번 쓴 오타.
(뒤따르는 $(\vec n \times \vec v) \cdot \vec n = 0$ 과 결론 "스칼라 부분 = 0"은 정확하다.)

### 2. L771 — Slerp에 가속/감속이 있다고 서술 (문서 내 4곳과 충돌)

> 큰 회전 … 60° ~ 180° 회전이 **부드러운 가속/감속** 으로 진행.

Slerp $\dfrac{\sin((1-t)\Omega)}{\sin\Omega}q_0 + \dfrac{\sin(t\Omega)}{\sin\Omega}q_1$ 은
대원호를 **일정한 각속도 $\Omega$** 로 지난다. 가속/감속이 존재하지 않는다.

같은 문서가 이를 네 번 정확히 못 박는다 — **L644**("t가 0→1로 균등 변화할 때, 회전이 균등 각속도로 진행"),
**L706**("접벡터의 크기는 t에 무관"), **L763**("Slerp는 균일"), **L897**("크기(각속도)는 일정").
가속/감속은 **Squad**(L718)나 **t 자체를 ease 곡선으로 재매핑**할 때 생기는 성질이지 Slerp의 성질이 아니다.

## math/part12_collision_sat.md — 확정 5건 (SAT 오류 방향이 5곳에서 반대)

### 1. L481 / L485 / L490 / L494 / L536 / L538 / L635 / L721 — SAT 불완전 축 집합의 오류 방향이 정반대

**이 문서의 가장 큰 문제다.** 같은 오해가 문서 전체에 반복된다.

SAT의 논리 구조상 **축 후보의 부분집합만 검사할 때 생길 수 있는 오류는 한 방향뿐이다.**

- 어떤 축 $\vec n$ 에서 두 투영 구간이 **겹치지 않으면**, 모든 $p \in A,\ q \in B$ 에 대해
  $p\cdot\vec n \ne q\cdot\vec n$ 이므로 $p \ne q$ — 두 도형은 **실제로 분리**다.
  즉 **"분리"라는 결론은 축을 몇 개만 검사해도 항상 참**이다(soundness).
- 반대로 검사한 축 어디에서도 분리가 안 보이면 "교차"로 결론내는데, 이건 **틀릴 수 있다**.

따라서 **외적 축 9개를 빠뜨리면 "실제로는 떨어져 있는 두 박스를 교차로 오판"(false positive)만
생기고, 진짜 교차를 놓치는 false negative는 원리상 불가능하다.**

그런데 문서는 일관되게 반대로 쓴다:

| L485 | "면들은 분리되어 보이지만 모서리 두 개가 **교차**한다" | 면 법선에서 분리가 보이면 **실제로 분리**다 |
| L490 (mermaid) | `면 법선만 검사 --> 교차 못 잡음` | `면 법선만 검사 --> 분리를 못 잡아 교차로 오판` |

### 2. L538 — 위 반전 때문에 제시된 검증 패턴이 버그를 검출하지 못함

> 검증 패턴: 두 박스를 모서리 정렬시킨 후 **살짝 찌부**시켜 SAT를 호출. **교차 결과**가 나와야 정확.

### 3. L188-190 — 정20면체의 면·꼭짓점 수가 뒤바뀜

> 일반 다면체 (예: **정20면체**) 는 **면 12개 + 모서리 30개** 정도. …
> - 면 법선: **12 + 12 = 24**

정20면체(icosahedron)는 **면 20 / 모서리 30 / 꼭짓점 12** 다 (오일러: 12 − 30 + 20 = 2).
**"면 12개"는 꼭짓점 수**이며, 면 12 + 모서리 30인 입체는 **정12면체(dodecahedron)** 다.

**"모서리 30 × 30 = 900"은 두 입체 모두에서 맞다**, 도형 이름만 정12면체로 바꿔도 수치가 맞는다.

### L482 — GJK 종료 판정식의 부호가 반대

> **[반영됨 · 2026-08-13]** 판정식은 2026-08-09 에 `진행도 = |v| + dot(newPt, dHat)` 로 정정됐다. 그러자 이 지적이 근거로 든 뒷문장("원점이 닿거나 안에 있으면 진행도가 음수에 도달")이 거꾸로 틀린 서술이 되어, 2026-08-13 에 "진행도는 상한 − 하한이므로 항상 0 이상" 으로 다시 썼다 (현재 `part13_collision_gjk_epa.md` L486).

```text
//   v       = 현재 심플렉스의 closest-to-origin (벡터)
//   dHat    = -v / |v| (원점 향한 단위 방향)
//   newPt   = support_{A⊖B}(dHat)
//   진행도  = |v| - dot(newPt, dHat)        // ← 부호 반대
```

`dHat = -v/|v|` 이므로 $\operatorname{dot}(newPt,\ dHat) = -\dfrac{\vec v \cdot w}{|v|} = -(\text{하한})$ 이다.

- **상한** = $|v|$ (현재 추정 거리)
- **하한** = $\dfrac{\vec v \cdot w}{|v|}$ (지지평면까지의 거리)
- **남은 여지** = 상한 − 하한 = $|v| + \operatorname{dot}(newPt,\ dHat)$

문서의 `|v| - dot(newPt, dHat)` 는 **상한 + 하한**이 되어, 완전히 수렴한 경우
($w$가 $v$ 방향, $\operatorname{dot}(newPt, dHat) = -|v|$)에도 **0이 아니라 $2|v|$** 를 준다.
표준 종료 조건 $|v|^2 - \vec v \cdot w \le \varepsilon$ 을 $|v|$ 로 나눈 형태와 비교해도 부호가 어긋난다.

**바로 다음 줄 L486이 이 정정을 뒷받침한다** — "원점이 Minkowski 차에 닿거나 안에 있으면
**진행도가 음수에 도달**해 거리 0(교차)으로 분기". 문서의 식 $|v| - \operatorname{dot}(newPt,dHat)$ 은
원점이 안에 있을 때 $|v| + (\text{양수})$ 가 되어 **결코 음수가 될 수 없다.**
올바른 식 $|v| + \operatorname{dot}(newPt, dHat)$ 이라야 L486이 성립한다.

### 1. L275 — Neumaier가 개선한 케이스가 정반대로 서술됨

> **Neumaier's algorithm**: Kahan의 변형. **입력보다 큰 누적합**에서 보정 정확도 ↑.

**반대다.** Kahan 원본의 보상항 `c = (t - sum) - y` 는 `t - sum` 이 `y`를 정확히 되찾아야 하는데,
그 가정은 **$|sum| \ge |y|$ 일 때 성립**한다. 즉 "누적합이 입력보다 클 때"는
**Kahan 원본이 이미 잘 동작하는 영역**이다.

Neumaier(1974, improved Kahan–Babuška)가 고친 것은 **$|x| > |sum|$**, 즉
**더하는 항이 현재 누적합보다 클 때**다. 두 크기를 비교해 큰 쪽/작은 쪽을 바꿔 처리한다:

```
t = sum + x
if |sum| >= |x|:  c += (sum - t) + x
else:             c += (x - t) + sum
```

### 2. L264 — 다이어그램의 수치가 float32에서 재현되지 않음

> **[반영됨 · 2026-08-13]** 2026-08-09 에 `Round`/`Save` 노드만 `0.00001` 로 고쳐 첫 노드의 `add 0.0001` 이 남아 다이어그램 안에서 값이 어긋나 있었다. 2026-08-13 에 `add 0.00001` 로 마무리 (현재 `part20_numerical_stability.md` L263).

> `Round[반올림: 1000.0001 → 1000.0 / 0.0001 손실]` … `Save[c = 0.0001 저장]`

$2^9 = 512 \le 1000 < 1024 = 2^{10}$ 이므로 **ULP(1000.0) = $2^{9-23} = 2^{-14} = 6.1035\times10^{-5}$**,
half-ULP = $3.0518\times10^{-5}$.
더하는 $0.0001$ 은 half-ULP의 **3.3배(= 1.638 ULP)** 라 **흡수되지 않는다.**

실제로 `1000.0f + 0.0001f` = **1000.0001220703125**(= 1000 + 2 ULP)로 1000.0이 되지 않는다.
손실분도 0.0001이 아니라 $|1.2207\times10^{-4} - 10^{-4}| = 2.207\times10^{-5}$ 이고
**부호도 반대**(참값보다 커지는 방향)라 Kahan의 `c`는 $+2.207\times10^{-5}$ 가 된다.

의도(더하는 값이 half-ULP 미만이라 통째로 흡수됨)를 살리려면 값을 바꿔야 한다 —
예를 들어 `1000.0f + 0.00001f` 는 $10^{-5} < 3.05\times10^{-5}$ 이라 실제로 1000.0이 된다.

### 3. L712 — 체크리스트가 본문이 배제한 방법을 권고

> [ ] 절대 epsilon 대신 **상대 epsilon** 사용

"순수 상대 epsilon은 0 근처에서 허용 오차가 0으로 수축한다"고 쓰고,
순수 상대 비교 코드를 주석 처리해 "너무 엄격"하다며 배제한 뒤
`AlmostEqual`에서 `std::max(1e-6f, 1e-6f * scale)` 즉 **절대+상대 혼합**을 권장한다.

그런데 §8.7 체크리스트는 본문이 배제한 순수 상대 epsilon을 그대로 권고 항목으로 올린다.
`max(absEps, relEps*scale)` 혼합으로 문구를 맞춰야 한다.
