## 들어가며

게임의 세계는 위치, 시간, 체력, 입력, 색, 식별자 같은 상태로 구성된다. 컴퓨터는 이 상태를 유한한 비트열로 저장한다. 표현 범위와 정밀도, 단위와 좌표계를 명시하지 않으면 같은 값이 시스템 경계에서 다른 뜻으로 해석된다.

수 표현은 수학의 세부 사항에 머물지 않는다. 큰 월드의 떨림, 물리 폭발, 네트워크 상태 불일치, 저장 파일 호환성은 모두 표현 계약이 깨진 결과일 수 있다. 이 글은 게임 상태를 비트로 표현할 때 필요한 기본 모델을 다룬다.

## 1. 비트와 정수

$w$비트 부호 없는 정수는 $0$부터 $2^w-1$까지 표현하며 연산은 $2^w$를 법으로 하는 모듈러 연산이다.

$$
(2^w - 1) + 1 \equiv 0 \pmod {2^w}
$$

C++의 부호 없는 정수 오버플로는 이 규칙을 따른다. 반면 부호 있는 정수 오버플로는 C++ 추상 기계에서 정의되지 않은 동작이다. 타이머와 시퀀스 번호에 래핑을 이용한다면 부호 없는 타입과 비교 규칙을 명시해야 한다. 래핑되는 시퀀스 번호의 순서 비교는 두 값의 거리가 표현 범위의 절반보다 작은 경우에만 정의된다.

작은 부호 없는 정수의 산술은 저장 타입의 폭으로 수행되지 않을 수 있다. 일반적인 환경에서 `uint8_t`와 `uint16_t`는 `int`로 승격된 뒤 연산되므로, 모듈러 산술은 저장 폭이 아니라 승격과 변환 이후 실제 연산 타입을 기준으로 설명해야 한다.

```cpp
std::uint8_t x = 255;
auto y = x + 1;                         // 일반적인 환경에서 int, 256
auto z = static_cast<std::uint8_t>(y);  // uint8_t로 변환한 결과 0
```

타입의 비트 수와 값의 뜻도 분리한다.

```cpp
using EntityId = std::uint32_t;
using Tick = std::uint32_t;

struct Health {
    std::int32_t current;
    std::int32_t maximum;
};
```

두 값이 모두 `uint32_t`라고 해서 서로 더하거나 비교해도 되는 것은 아니다. 식별자, 시간 틱, 바이트 크기는 표현이 같아도 의미가 다르다. 강한 타입이나 구조체는 잘못된 단위 조합을 컴파일 단계에서 줄인다.

비트 필드는 저장 공간을 줄이지만 갱신 비용과 동시성 단위가 달라진다. C++에서는 인접한 일정한 비트 필드들이 하나의 메모리 위치로 취급될 수 있으므로, 같은 워드를 공유하는 필드 하나를 갱신하는 것도 읽기-수정-쓰기가 되고 다른 필드와의 동시 접근이 데이터 레이스가 될 수 있다. 같은 캐시 라인을 공유해 생기는 일관성 트래픽은 이와 별개의 하드웨어 비용이다.

## 2. 부동소수점과 오차

일반적인 이진 부동소수점 값은 부호, 지수, 유효숫자로 표현된다.

$$
x = (-1)^s \times m \times 2^e
$$

고정된 유효숫자 비트 수 때문에 절대 간격은 값의 크기와 함께 커진다. 원점 부근에서 구분할 수 있던 작은 차이가 큰 좌표에서는 같은 비트 패턴으로 반올림될 수 있다.

부동소수점 형식과 반올림, 예외값의 표준 계약은 [IEEE 754-2019](https://standards.ieee.org/ieee/754/6210/)가 정의한다. 언어와 하드웨어가 제공하는 세부 동작은 해당 구현 계약도 함께 확인해야 한다.

10진 소수 대부분은 이진 유한 소수로 정확히 표현되지 않는다. 따라서 다음 비교는 계산 경로에 따라 실패할 수 있다.

```cpp
if (accumulatedTime == targetTime) {
    Trigger();
}
```

비교 기준은 값의 의미에 맞춰 정한다.

$$
|a-b| \le \epsilon_{\text{abs}} +
          \epsilon_{\text{rel}}\max(|a|,|b|)
$$

절대 오차는 0 근처를 다루고 상대 오차는 큰 값의 비례 오차를 다룬다. 모든 시스템에 하나의 `EPSILON`을 공유하면 단위와 허용 오차가 섞인다. 접촉 거리, 애니메이션 시간, 색 계산에는 서로 다른 허용 오차가 필요하다.

값 비교와 시간 이벤트는 다른 문제다. 일회성 이벤트의 핵심은 두 값이 가까운지가 아니라 목표 시각을 통과했는지인 경우가 많다. 시간이 0.09에서 0.12로 증가하고 목표가 0.10이면 작은 허용 오차로 바꿔도 이벤트를 놓친다. 일회성 이벤트는 이전 시간 < 목표 시간 ≤ 현재 시간처럼 경계 통과로 판정하고, 주기 이벤트는 건너뛴 주기 수와 따라잡기 정책을, 결정적 시뮬레이션은 정수 틱과 명시적 래핑 규칙을 사용한다.

오차는 연산 순서에도 의존한다.

- 크기가 크게 다른 값을 더하면 작은 값의 유효 비트가 사라질 수 있다.
- 거의 같은 두 값을 빼면 유효숫자가 상쇄될 수 있다.
- 긴 합산은 반올림 오차를 누적한다.
- `NaN`은 자기 자신과도 같지 않으며 비교식의 분기를 예상과 다르게 만든다.

정규화가 필요한 벡터의 길이가 0에 가까우면 나눗셈이 큰 오차나 `NaN`을 만든다. 입력 범위를 확인한 뒤 기본 방향을 선택하거나 연산 자체를 생략해야 한다.

고정소수점은 값 $r$을 정수 $q$와 스케일 $S$로 표현한다.

$$
r \approx \frac{q}{S}
$$

동일한 정수 연산 규칙을 사용하기 쉬운 대신 범위, 스케일, 곱셈 중간값의 오버플로를 직접 관리해야 한다. 고정소수점이 자동으로 결정성을 보장하는 것은 아니다. 연산 순서, 오버플로 정책, 플랫폼별 정수 규칙도 같아야 한다.

## 3. 단위와 좌표계

값은 숫자와 단위의 쌍이다. 위치가 미터인지 센티미터인지, 각도가 라디안인지 도인지, 시간이 초인지 틱인지 명시하지 않으면 수치가 맞아도 물리적 의미가 틀린다.

```cpp
struct Seconds {
    double value;
};

struct Meters {
    double value;
};
```

좌표는 기준 프레임에 대한 표현이다. 로컬 좌표의 점을 월드 좌표로 옮기는 변환을 $T_{\text{world}\leftarrow\text{local}}$이라 쓰면 합성 방향이 드러난다.

$$
p_{\text{world}} =
T_{\text{world}\leftarrow\text{local}}p_{\text{local}}
$$

행렬을 행 우선으로 저장하는지와 벡터를 행·열 중 어느 방향으로 곱하는지는 별개의 선택이다. 메모리 저장 순서만 보고 수학적 곱셈 방향을 추론하면 안 된다.

좌표계 계약에는 최소한 다음 항목이 들어간다.

- 오른손·왼손 좌표계
- 위쪽과 전방 축
- 월드 단위
- 각도 단위와 회전 순서
- 행렬의 벡터 곱 방향
- 깊이 범위와 화면 원점

큰 월드는 카메라 근처 좌표를 별도로 유지하거나 원점을 이동해 부동소수점 간격을 제어할 수 있다. 이때 렌더링 좌표와 권위 있는 월드 좌표를 같은 타입으로 섞지 않는 것이 중요하다.

## 4. 양자화와 직렬화

양자화는 연속 범위의 값을 유한한 정수 코드로 바꾼다. 범위 $[x_{\min},x_{\max}]$를 $b$비트로 균등 양자화하면 단계 크기는 대략 다음과 같다.

$$
\Delta = \frac{x_{\max}-x_{\min}}{2^b-1}
$$

비트 수를 줄이면 저장·전송 비용은 감소한다. 입력이 범위 안에 있고 가장 가까운 단계로 반올림하며 $b>0$, $x_{\min}<x_{\max}$이면 최대 양자화 오차는 약 $\Delta/2$다. 범위 밖 입력을 끝단으로 포화시키면 오차가 그보다 커질 수 있으므로, 범위 안 양자화 오차와 범위 밖 포화 처리를 분리해 정의한다. 위치를 양자화할 때는 월드 전체 범위보다 관심 영역의 로컬 범위를 사용하면 같은 비트 수로 더 높은 정밀도를 얻을 수 있다.

직렬화 형식은 메모리 구조체를 그대로 복사하는 일이 아니다. 구조체에는 패딩, 플랫폼 엔디언, 포인터, ABI 차이가 포함될 수 있다.

```cpp
struct PacketWriter {
    void WriteU32(std::uint32_t value);
    void WriteF32(float value);
};
```

바이트 순서, 필드 순서, 길이, 버전, 허용 범위를 형식의 계약으로 둔다. 수신 측은 길이와 범위를 검증한 뒤 값을 구성해야 한다. 신뢰할 수 없는 길이를 그대로 할당 크기로 사용하면 메모리 고갈이나 범위 초과가 발생한다.

식별자는 객체 주소와 분리한다. 주소는 실행마다 달라지고 객체 이동과 해제에 따라 무효화된다. 저장·네트워크 경계에서는 안정적인 ID와 세대 번호 같은 명시적 참조를 사용한다.

## 5. 표현 불변식 검증

표현을 선택할 때 다음 불변식을 문서와 테스트에 남긴다.

| 상태 | 불변식 예 |
|---|---|
| 체력 | $0 \le current \le maximum$ |
| 정규화 벡터 | 사용 중이면 길이가 허용 오차 안에서 1 |
| 타임스탬프 | 같은 시간축과 래핑 비교 규칙 사용 |
| 직렬화 | encode-decode 후 허용 오차 안에서 동일 |
| 좌표 | API 경계에서 단위와 기준 프레임이 명시됨 |

경계값 테스트는 정상 범위의 중앙값보다 중요하다. 0, 최댓값, 래핑 직전과 직후, `NaN`, 무한대, 매우 큰 좌표, 거의 평행한 벡터를 입력한다.

직렬화에는 왕복 속성도 사용할 수 있다.

$$
decode(encode(x)) = x
$$

손실 양자화라면 정확한 등호 대신 허용 오차와 범위 보존을 검사한다.

$$
|decode(encode(x))-x| \le \frac{\Delta}{2}
$$

---

## 결론

게임 상태는 수학적 값이 아니라 유한한 비트열로 실행된다. 정수의 범위와 래핑, 부동소수점 간격과 오차, 단위와 좌표계, 직렬화 형식을 명시해야 같은 상태가 시스템 경계를 넘어도 같은 뜻을 유지한다.

좋은 표현은 가장 많은 비트를 쓰는 표현이 아니다. 필요한 범위와 정확도를 만족하면서 메모리와 대역폭 비용을 통제하고, 경계값과 왕복 속성으로 불변식을 검증할 수 있는 표현이다.
