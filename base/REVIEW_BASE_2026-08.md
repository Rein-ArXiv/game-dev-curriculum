## base/part01_cost_models.md — 확정 1건

### 1. L75 — 심화 문서가 반례로 부정한 통념을 무조건 단정 (심화문서와모순) — **[반영됨 2026-08-13 / 파생 지적 1건 이월]**

> 연결 리스트 삭제는 삭제할 노드를 이미 알고 있을 때 $O(1)$이다. 값을 찾는 과정까지 포함하면 $O(n)$이다.

**"노드를 이미 앎"은 단일 연결 리스트에서 $O(1)$의 충분조건이 아니다.**
소유 문서 `parts/part09_intrusive_list.md` L328-339가 **정확히 이 통념을 반례로 부정**한다 —
함수 시그니처가 `remove(Node* node)`, 즉 노드를 이미 아는 상황인데도:

```cpp
// 단일 연결 리스트 - 제거 시 O(n)
while (prev->next != node) prev = prev->next;   // O(n) 탐색!

// 이중 연결 리스트 - 제거 시 O(1)
```

**판정: 심화 문서가 옳다.** `prev` 포인터가 없으면 선행 노드 탐색이 불가피하다.

두 번째 절도 독립적으로 부정확하다 — "값을 찾는 과정까지 포함하면 $O(n)$"은 $O(n)$의 원인을
**값 탐색으로 한정**하는데, 단일 연결 리스트는 값 탐색이 없어도 $O(n)$이다.

이 지적이 "요약의 생략"이 아닌 이유: **이 절의 주제 자체가 "복잡도에는 조건을 붙여야 한다"** 이고,
형제 불릿들(해시 분포·적재율, 상각 vs 단일 연산, 균형 vs 비균형 BST)은 모두 판별 조건을
정확히 달고 있다. **이 불릿만 기준을 어긴다.** part01 전체에서 "연결 리스트"는 이 줄이 유일해
앞에서 이중 연결로 한정하는 문맥도 없다.

**정정**: 최소 수정은 "연결 리스트" → **"이중 연결 리스트"**.
(`base/part03_data_structures.md` L38·L55도 같은 축약 "노드를 알면 $O(1)$"을 쓴다.)

> **[상태 2026-08-13]** part01 L75는 **반영됨** — 현재 본문은 "이중 연결 리스트 삭제는 …"이다.
> 괄호 안의 **파생 지적(part03 L38·L55)은 이월** — 두 줄 모두 검수 당시 표현 그대로다.
> 상세는 문서 끝 [`## 반영 상태 (2026-08-13)`](#반영-상태-2026-08-13) 의 이월 목록 D-1 참조.

## base/part10_network_fundamentals.md — 확정 1건

### 1. L109 — 부정 서술어가 탈락해 명제가 뒤집힘 (개정 잔재) — **[반영됨 2026-08-13]**

> TCP는 손실된 바이트를 재전송하고 앞선 바이트가 복구될 때까지 뒤 바이트를 애플리케이션에 **순서대로 공개한다**.

한국어 「A할 때까지 B한다」는 **A 이전 구간에 B가 성립**한다는 뜻이므로, 이 문장은
"앞선 바이트가 복구되기 **전에** 뒤 바이트를 공개한다"를 단정한다.
TCP의 in-order delivery와 정반대이고, **"순서대로"와도 자기모순**이다
(앞이 안 왔는데 뒤를 순서대로 공개할 수는 없다).

**바로 다음 문장**("오래된 실시간 상태가 최신 상태의 전달을 막는 head-of-line 지연을 만들 수 있다")은
**보류를 전제해야만 성립**한다.

소유 문서 `network/part02_transport.md` §14(L246-254)는
`[N-1까지 전달됨][구멍 N][N+1]…` 그림과 함께 "애플리케이션은 여기서 멈춘 채 N의 재전송을
기다린다", "구멍 앞에서 기다리는 것 외에 방법이 없다"로 못박는다.

**결정적으로 같은 저장소의 `network/part06_game_transport_protocol.md` L35가
동일 명제를 "순서가 복구될 때까지 애플리케이션에 넘기지 않는다"로 부정형을 붙여 서술**한다 —
base 쪽에서 부정 서술어가 탈락한 개정 잔재임이 확인된다.

**정정**: "…뒤 바이트를 애플리케이션에 **공개하지 않는다**(복구된 뒤에야 순서대로 공개한다)."
