## 들어가며

알고리즘은 입력을 출력으로 바꾸는 절차이며, 두 가지 질문에 답해야 한다. 결과가 왜 맞는가, 필요한 자원이 입력과 함께 어떻게 증가하는가. 게임에서는 여기에 마감 시간과 근사 허용 범위가 더해진다.

길찾기, 정렬, 충돌 후보 생성, 절차적 생성은 서로 다른 문제처럼 보이지만 상태, 전이, 불변식, 종료 조건으로 분석할 수 있다. 이 글은 알고리즘을 선택하고 검증하는 공통 언어를 다룬다.

## 1. 문제와 계약

알고리즘을 구현하기 전에 입력, 출력, 허용 조건을 적는다.

```text
입력: 음수가 아닌 가중치를 가진 유한 그래프, 시작점 s, 목표점 g
출력: s에서 g까지의 최소 비용 경로 또는 도달 불가
제약: 그래프는 실행 중 변경되지 않음
```

“가장 가까운 적”도 거리의 정의에 따라 다른 문제다. 유클리드 거리, 이동 가능한 경로 비용, 화면 공간 거리, 위협 점수는 같은 결과를 주지 않는다. 목적 함수를 명확히 하지 않으면 빠른 구현을 만들어도 올바른 대상을 고를 수 없다.

전제 조건은 구현의 일부다. 이진 탐색은 입력이 정렬되어 있어야 하고, 다익스트라 알고리즘은 음수 가중치를 허용하지 않는다. 전제가 깨질 수 있다면 호출 경계에서 검증하거나 전제를 유지하는 자료구조가 필요하다.

## 2. 정확성 증명

반복 알고리즘은 루프 불변식으로 설명할 수 있다. 루프 불변식은 반복 전후에 항상 참인 명제다.

정렬된 배열에서 이진 탐색을 수행할 때 다음 불변식을 둘 수 있다.

```text
찾는 값이 배열에 존재한다면 현재 구간 [lo, hi) 안에 있다.
```

각 반복이 이 명제를 보존하고 구간 길이를 줄이면, 종료 시 결과의 존재 여부를 판단할 수 있다. 정확성은 다음 두 부분으로 나뉜다.

- 부분 정확성: 종료한다면 결과가 계약을 만족한다.
- 종료성: 각 단계에서 well-founded measure가 감소해 결국 끝난다.

그래프 탐색에서는 방문 집합과 프런티어의 의미가 불변식이다. 노드를 너무 일찍 방문 완료로 표시하거나 더 좋은 경로를 발견했는데 비용을 갱신하지 않으면 최단 경로 보장이 깨진다.

게임 알고리즘은 때로 최적해 대신 유효한 해를 요구한다. 이 경우에도 정확성 계약이 사라지는 것은 아니다. “장애물을 통과하지 않는 경로”, “제한 시간 안에 반환”, “오차가 상한 이하”처럼 보장 수준을 다시 정의한다.

## 3. 복잡도와 입력 분포

시간 복잡도는 기본 연산의 증가율을 모델링한다.

$$
T(n) \in O(f(n))
$$

최악, 평균, 기대, 상각 비용은 서로 다른 주장이다. 무작위 피벗 퀵정렬의 기대 시간과 특정 입력에서의 최악 시간, 동적 배열의 상각 삽입 비용을 섞으면 안 된다.

공간 복잡도에는 입력 자체를 제외한 보조 공간인지, 결과 저장 공간까지 포함하는지 명시한다. 재귀 깊이가 입력에 비례하면 힙 할당이 없어도 스택 공간 $O(n)$을 사용할 수 있다.

게임의 입력은 독립 균등분포가 아닌 경우가 많다.

- 적은 플레이어 주변에 군집한다.
- 경로 그래프는 격자나 내비게이션 메시의 기하 구조를 가진다.
- 정렬 입력은 이전 프레임 순서와 비슷하다.
- 네트워크 패킷 손실은 연속적으로 몰릴 수 있다.

평균 복잡도 분석의 분포가 실제 데이터와 다르면 벤치마크와 운영 결과도 달라진다. 퇴화 입력과 실제 분포를 모두 테스트한다.

## 4. 탐색과 경로 찾기

너비 우선 탐색은 간선 비용이 동일한 그래프에서 최소 간선 수 경로를 찾는다. 다익스트라 알고리즘은 음수가 아닌 가중치에서 현재까지 알려진 비용이 가장 작은 노드를 확정한다.

A*는 누적 비용 $g(n)$과 목표까지의 추정 비용 $h(n)$을 합쳐 우선순위를 정한다.

$$
f(n) = g(n) + h(n)
$$

휴리스틱이 실제 남은 비용을 넘지 않으면(허용적) 최적 경로를 보장할 수 있다. 다만 닫힌 노드를 재개방하지 않는 구현은 허용성만으로 최적성이 보장되지 않으므로, 더 싼 경로를 발견하면 닫힌 노드를 다시 여는 규칙이 필요하다. 목표는 발견 즉시가 아니라 최적 비용으로 꺼낼 때 종료하고, 목표에서의 휴리스틱 값이 0인지도 확인한다. 일관성까지 만족하면 다음 조건이 성립한다.

$$
h(n) \le c(n,n') + h(n')
$$

A*의 최적성 조건과 휴리스틱의 역할은 Hart, Nilsson, Raphael의 [원 논문](https://ai.stanford.edu/~nilsson/OnlinePubs-Nils/PublishedPapers/astar.pdf)에 정리돼 있다. 실제 구현은 그래프 변경, 중복 큐 항목과 유한 정밀도까지 별도로 처리해야 한다.

우선순위 큐에서 같은 노드의 오래된 항목이 남을 수 있으므로 꺼낸 비용이 현재 최선 비용과 같은지 확인한다. 새 비용이 엄격히 개선될 때만 삽입하고, 비용에는 `NaN`이나 오버플로가 없어야 하며, 탐색 예산 소진과 도달 불가를 구분해야 한다.

```cpp
while (!open.empty()) {
    NodeEntry current = open.top();
    open.pop();

    if (current.g != bestCost[current.node]) {
        continue;
    }
    // 이 시점의 항목만 확장한다.
}
```

경로 찾기의 실제 비용은 정점과 간선 수뿐 아니라 휴리스틱 품질, 장애물 배치, 그래프 표현, 메모리 지역성에 의존한다. 모든 NPC가 매 프레임 전체 경로를 다시 찾는 대신 목표 변경, 경로 무효화, 시간 예산을 기준으로 작업을 분산할 수 있다.

## 5. 무작위성과 근사

의사난수 생성기(PRNG)는 내부 상태에서 결정적인 수열을 만든다. 같은 알고리즘, 초기 상태, 호출 순서가 같으면 같은 결과가 나온다. 재현 가능한 월드 생성에는 시드만 아니라 알고리즘 버전과 소비 순서도 계약에 포함해야 한다.

난수 원본을 원하는 분포로 변환할 때 모듈로 연산은 편향을 만들 수 있다.

```cpp
// bound > 0을 전제로 한다. 생성기 범위가 bound의 배수가 아니면 일부 결과가 더 자주 나온다.
std::uint32_t biased = rng() % bound;
```

표준 분포나 rejection sampling을 사용하고 통계 검정으로 결과를 확인한다. 다만 표준 난수 분포가 원본 난수를 분포로 변환하는 알고리즘은 구현 정의이므로, 엔진과 시드가 같아도 서로 다른 표준 라이브러리에서 분포 결과까지 같다고 가정할 수 없다. 통계적 타당성과 비트 단위 재현성을 분리해 검증한다. 암호학적 비밀에 일반 게임용 PRNG를 사용해서는 안 된다.

실시간 시스템은 시간 예산을 넘기지 않기 위해 근사 알고리즘을 사용한다. 근사에는 세 종류의 계약이 있다.

| 종류 | 보장 |
|---|---|
| 오차 제한 | 결과 오차가 정해진 범위 이내 |
| anytime | 중간 결과가 유효하며 시간이 늘수록 개선 |
| 확률적 | 정해진 확률로 품질이나 성공 조건 만족 |

“대충 충분히 좋다”는 검증할 수 없다. 경로 비용이 최적의 몇 배 이내인지, 생성 실패율이 얼마인지, 시간 예산 초과 시 어떤 결과를 반환하는지 정의한다.

## 6. 검증 전략

예제 몇 개가 통과해도 알고리즘이 맞다는 증거는 부족하다. 다음 방법을 함께 사용한다.

- 작은 입력을 완전 탐색해 기준 결과와 비교한다.
- 속성 기반 테스트로 정렬성, 보존성, 대칭성 같은 불변식을 검사한다.
- 경계값과 퇴화 입력을 생성한다.
- 무작위 테스트의 시드와 입력을 실패 로그에 남긴다.
- 성능 테스트는 입력 크기와 분포를 단계적으로 바꾼다.

정렬 결과의 핵심 속성은 순서와 원소 보존이다.

```text
모든 i < n-1에 대해 output[i] <= output[i + 1]
input과 output의 원소별 빈도는 동일
```

경로 탐색은 반환된 간선이 실제로 연결되는지, 장애물을 통과하지 않는지, 비용 합계가 보고된 비용과 같은지 검사한다. 최적성은 작은 그래프에서 완전 탐색이나 검증된 기준 구현과 비교할 수 있다.

복잡도 주장도 실험할 수 있다. 입력 크기를 두 배로 늘릴 때 시간과 메모리 증가율을 기록하되, 캐시 경계와 시스템 잡음을 고려해 이론과 실측의 차이를 해석한다.

---

## 결론

알고리즘은 코드 조각이 아니라 문제 계약, 정확성 논증, 자원 비용의 결합이다. 전제 조건과 불변식을 명시하면 어떤 입력에서 결과를 믿을 수 있는지 설명할 수 있다.

게임에서는 최적해보다 시간 안에 나오는 유효한 해가 더 중요할 수 있다. 그 경우에도 오차, 실패율, 종료 조건을 계약으로 만들어야 한다. 정확성 검증과 실제 입력 분포를 사용한 성능 측정이 함께 있어야 선택을 정당화할 수 있다.
