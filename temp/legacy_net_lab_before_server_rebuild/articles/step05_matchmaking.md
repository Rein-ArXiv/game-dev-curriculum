## 들어가며

매치메이킹은 가장 비슷한 사람을 고르는 정렬 문제가 아니다. 오래 기다리지 않게 하면서도 공정한 매치를 만드는 온라인 최적화 문제다. Progressive Widening은 대기 시간이 늘수록 허용 MMR 차이를 넓힌다.

## 1. 큐 모델

플레이어는 MMR과 입장 시각을 가진다. Scene은 spawn rate에 따라 새 플레이어를 넣고, 매 tick 매칭 가능한 쌍을 찾는다.

같은 MMR 분포와 난수 시드를 사용해야 widening 정책만 바꾼 비교가 가능하다.

## 2. 허용 범위

대기 시간 $t$인 플레이어의 허용 차이를 다음처럼 둔다.

$$
w(t)=w_0+s\,t
$$

$w_0$는 초기 품질 기준, $s$는 widening slope다. slope가 크면 대기는 줄지만 평균 MMR 차이가 커진다.

두 플레이어를 매칭할 때는 한쪽 범위만 보지 않고 서로의 허용 범위를 모두 만족시키는 정책을 명시해야 한다.

```cpp
inline bool MutuallyCompatibleMatch(int difference,
                                    float waitA, float waitB,
                                    float base, float slope) {
    const float allowedA = std::max(0.0f, base + waitA * slope);
    const float allowedB = std::max(0.0f, base + waitB * slope);
    return difference >= 0 &&
           (float)difference <= std::min(allowedA, allowedB);
}
```

오래 기다린 플레이어의 넓은 범위만 사용하면 방금 입장한 상대가 동의하지 않은 품질의 매치를 강제한다. `min(allowedA, allowedB)`는 양쪽이 모두 받아들일 때만 매치한다.

## 3. 매칭과 제거

한 플레이어를 여러 번 매칭하지 않도록 쌍을 확정한 뒤 큐에서 안전하게 제거한다. 순회 중 벡터를 즉시 erase하면 인덱스를 건너뛸 수 있으므로, 매칭 표시 후 일괄 제거하거나 뒤에서부터 지운다.

## 4. 지표

- 현재 큐 크기
- 분당 매치 수
- 평균·최대 대기 시간
- 평균·상위 백분위 MMR 차이

평균만 보면 오래 굶는 플레이어를 놓친다. 실제 시스템에서는 P95/P99 대기와 지역·파티 크기별 분포가 필요하다.

## 5. 검증 실험

1. slope 0에서 품질과 큐 증가를 본다.
2. slope를 높여 평균 대기와 평균 MMR 차이를 비교한다.
3. spawn rate가 처리량보다 높을 때 큐가 계속 자라는지 본다.
4. 낮은 인구 분포에서 widening의 필요성을 확인한다.
5. 같은 시드에서 정책만 바꿔 결과를 비교한다.

매치메이킹 정책의 정답은 단일 숫자가 아니다. *대기 시간 분포와 매치 품질 분포 사이의 선택* 이다.

---

## 결론

대기 시간에 따라 허용 MMR 범위를 넓히는 정책을 시뮬레이션하고 평균뿐 아니라 최대 대기, 매치 품질, 처리량을 함께 측정한다. 같은 유입 분포와 시드에서 정책만 바꿔 공정한 비교가 가능하다.

현재 큐는 개인 플레이어와 합성 MMR 분포만 다룬다. 파티 보존, 지역과 지연 시간, 역할 조합, 재매칭 회피, P95·P99 공정성은 포함하지 않으므로 실제 서비스 정책으로 그대로 사용할 수 없다.
