## 들어가며

`net_lab`은 실제 소켓 통신을 만드는 프로젝트가 아니다. 넷코드가 지연·지터·손실·불확실한 원격 입력에 어떻게 반응하는지를 재현 가능한 작은 시뮬레이션으로 분리해 보는 도구다.

첫 단계에서는 Scene 골격과 공통 시간 모델을 만든다. 이후 각 Scene은 실제 인터넷 대신 결정론적 지연 큐를 사용한다. 같은 시드와 설정이면 같은 패킷 도착 순서와 같은 결과가 나와야 비교가 가능하다.

## 1. 완성 목표

공유 골격은 다음 책임만 가진다.

- 탭으로 Scene 전환
- 캔버스·패널·푸터 레이아웃
- Scene의 Update와 Draw 분리
- 프레임 시간 EMA 표시
- Scene 진입 시 Reset 가능한 생명주기

각 Scene은 자체 시뮬레이션 tick, 패킷 큐, 측정치를 소유한다. 메인 루프는 Rollback이나 Prediction의 내부 규칙을 몰라야 한다.

## 2. Scene 아키텍처

```cpp
class IScene {
public:
    virtual ~IScene() = default;
    virtual std::string_view Name() const = 0;
    virtual void OnEnter() {}
    virtual void Update(float dt) = 0;
    virtual void DrawWorld(int x, int y, int w, int h) = 0;
    virtual void DrawPanel(int x, int y, int w, int h) = 0;
};
```

Scene이 바뀌면 `OnEnter`에서 실험 상태를 초기화한다. 장면 전환 전의 패킷 큐나 누적 통계가 남으면 같은 설정의 비교가 깨진다.

## 3. 시간 단위 분리

넷코드에는 최소 세 시간이 있다.

- 렌더 프레임 시간 `dt`
- 고정 시뮬레이션 tick
- 인공 네트워크의 전달 시각 또는 전달 tick

렌더 프레임마다 시뮬레이션을 한 번만 진행하면 FPS 변화가 네트워크 결과를 바꾼다. accumulator로 고정 tick을 진행하고, 패킷은 `deliverTick` 또는 `arriveTime` 기준으로 꺼낸다.

## 4. 측정 규칙

각 Scene은 결과 숫자와 비용 숫자를 분리한다.

| 종류 | 예 |
|---|---|
| 체감 결과 | 입력 지연, 위치 오차, 매치 품질 |
| 보정 비용 | rollback/s, 재시뮬 깊이, pending 입력 |
| 정확성 | 상태 해시, 불변식 위반, 손실·재정렬 수 |

좋은 넷코드 비교는 “부드럽다”만 말하지 않는다. 무엇을 숨겼고 그 대가가 어디로 이동했는지 함께 측정한다.

## 5. 검증 기준

1. 같은 시드와 설정에서 결과가 반복된다.
2. Draw 호출은 시뮬레이션 상태를 바꾸지 않는다.
3. Scene 전환 후 누적 통계가 초기화된다.
4. 렌더 FPS를 바꿔도 고정 tick 결과가 유지된다.
5. Welcome Scene만으로 빌드·실행된다.

---

## 결론

렌더 시간, 시뮬레이션 tick, 네트워크 전달 시간을 분리하고 Scene별 상태와 통계를 격리한 실행 골격을 만들었다. 같은 시드와 설정에서 렌더 FPS가 달라도 고정 tick 결과가 유지되는 것이 넷코드 실험의 기준선이다.

현재 실행 경로에는 네트워크 알고리즘이 없으므로 지연 은폐나 동기화 정확성을 보장하지 않는다. 이 단계의 결과는 알고리즘 비교에 필요한 시간 모델, 재현성, 측정 채널까지다.
